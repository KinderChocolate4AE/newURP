**2026-07-27 · `docs/26` §2(결과 골격)를 대체 · `docs/27` §2–§3(사다리) 개정**

---

## 1. `N*` 헤드라인이 왜 틀렸나

**Hyunjun 지적**: *"'개수' 자체는 굳이 net 없더라도 갔다 박으면 되니까."*

맞다. limiter는 `kill_radius = 2.0`짜리 kamikaze다. 개수를 헤드라인에 놓으면 리뷰어의 첫 질문이 **"그러면 네트가 왜 필요한가"** 가 되고, 논문이 자기 finisher를 논증에서 밀어낸다. 치명적이다.

부수적으로 이건 비준된 novelty 위치에서의 **표류**이기도 하다. 기존 판정은 *"non-destructive finisher의 exchange를 협력 shaping이 움직인다"* 였는데, `N*`로 가면서 generic multi-agent pursuit 쪽으로 흘렀다. 그 방향엔 이미 围捕/encirclement 문헌이 가득하다.

**`N*`는 폐기가 아니라 강등한다** — §5 작동영역의 *비용 축*으로. 헤드라인이 아니다.

## 2. 실제 기여 — 비손실 격추 + 위협-조향

```
문제   비손실 격추 (capture, not kill)
       부수피해·잔해·포렌식 -> last-mile 도심에서 파괴적 요격은 답이 아니다
       ⇒ "그냥 박으면 된다"가 애초에 허용되지 않는 문제 설정

기전   limiter의 살상반경을 실행되지 않는 위협으로 쓴다.
       조향 입력이지 격추 수단이 아니다.

전제   손실 회피형 적응-반응 공격자.
       위협을 회피하기 때문에 조향이 성립한다 = 양치기의 성립 조건

규율   limiter가 실제로 충돌하면 부분 실패로 채점한다.
       이 한 줄이 "박으면 된다"를 봉쇄하고 논문을 조향 문제로 만든다.
```

### 2.1 env는 이미 옳게 구현돼 있다 (실사 결과)

`env.py` L353:
```python
limiter_loss = float(sum(1 for c in lim_pos
                         if np.linalg.norm(p_att - c) <= self.kill_radius))
```
**limiter가 살상반경 안에 들어와도 공격자는 죽지 않는다.** 비용(`l3 = 0.5`)만 발생하고 에피소드는 계속된다. S1 비준 문구 그대로다 — *"kamikaze limiter = cost-bearing shaping pressure (NOT a consumable missile)"*.

즉 **엔진은 맞고 프레이밍만 틀렸다.** 다만 이 모델링 선택은 논문에서 **명시적으로 정당화되어야** 한다:

> 기동 회피 중인 표적에 대한 자폭형 요격체의 실제 명중확률은 낮다. 따라서 살상반경은 *보장된 격추*가 아니라 *공격자가 회피해야 할 위험*이다. limiter는 확률적 위협이고, 그 위협의 공간 배치가 조향 입력이다.

이게 없으면 리뷰어는 "왜 kamikaze가 안 죽이냐"로 들어온다.

### 2.2 채점 개정

현행 4분할을 5분할로:

```
NET_CAPTURE      비손실 포획 — 목표
KINETIC_CONTACT  limiter가 실제 살상반경에 접촉 — 성공이 아니라 부분 실패
PENETRATED       실패
SPENT_FAIL       발사 소진
TRUNCATED        우측 절단
```

**순도 지표**: 배치 `N` · 실접촉 `limiter_contact`.
`N기 배치 · 0기 접촉 · NET_CAPTURE` = **순수 조향**. 접촉이 늘수록 물리적 차단에 의존한 것.

구현 주의: 현행 `limiter_loss`는 **스텝별 합**이라 같은 limiter가 여러 스텝 중복 계수된다. 에피소드 라벨용으로는 *"어느 limiter가 한 번이라도 살상반경에 들어왔는가"* 의 집합 크기를 따로 세야 한다.

## 3. λ — 숨어 있던 최대 가정

`agents/adversary.py`:
```python
if dist <= repel_margin * kill_radius:                # repel_margin = 1.0 (env 하드코딩)
    strength = (repel_margin*kill_radius - dist) / (repel_margin*kill_radius)
    a_rep += a_att_max * (1.0 + strength) * _unit(d, fwd)
```

**반발 크기가 전권한 이상(`≥ a_att_max`)이고, 발동 거리는 살상반경 그 자체(2.0 m)다.**
⇒ **λ = ∞ 가 하드코딩되어 있고 anticipation = 0** (최대로 겁먹지만 최후 순간에만).

**지금까지 프로젝트의 모든 결과가 "최대로 겁먹는 공격자" 가정 위에 있었고, 그게 양치기가 성립한 유일한 이유다.** 이 가정은 한 번도 변수로 취급된 적이 없다.

### 3.1 λ의 올바른 정의

λ는 *기체 손실 회피*가 아니라 **조기 손실에 의한 임무 실패 회피**다.

> 자폭드론도 표적 500 m 앞에서 요격되면 실패다. 따라서 목표 지향 공격자는 모두 `λ > 0`이다.
> λ의 크기는 **단위당 가치 / 소모 허용도**로 결정된다 — 소모품 다수 편대는 λ 작고, 단일 고가 플랫폼·유인 조종은 λ 크다.

이게 메모의 exchange-economics 축과 직결되지만, S9 레이어를 짓지 않고도 쓸 수 있는 형태다.

### 3.2 λ = 0 은 결정적 음성 대조군

```
λ = 0 에서도 NET_CAPTURE율이 유지되면
  -> 그건 양치기가 아니라 물리적 차단이다
  -> C1의 기전 주장 철회
```
현실 위협 모델이 아니라 **기전 증명용 대조군**이다. 이 프로젝트의 negative-control 규율에 정확히 부합한다.

## 4. 두 주장으로 분리 (논문은 하나)

```
C1 (개념·기전)
   비손실 격추는 λ > 0 위에서 위협-조향으로 성립하며,
   그 작동영역은 (λ, a_att) 평면에서 유계다.
   반증: 어떤 λ에서도 비손실 경로가 파괴적 차단보다 낫지 않음
        또는 λ=0에서 성능이 유지됨(기전 부재)

C2 (방법)
   그 조향을 학습으로 만들면 정적 배치보다 작동영역이 넓다.
   반증: learned ≈ static
```

**독립 반증 가능하다.** C1이 죽어도 C2가 살 수 있고(조향은 되지만 학습이 무의미), C2가 죽어도 C1이 남는다(개념은 성립, 학습은 불필요). 논문이 통째로 무너지지 않는다.

### 분할하지 않는 이유

| | |
|---|---|
| C1 단독 | position paper. Q1 약함 |
| C2 단독 | 방금 기각한 generic "몇 기 필요한가" |
| 상호 하중 | C1이 *왜 어려운지*, C2가 *어떻게 푸는지*. 떼면 둘 다 약해짐 |
| 규율 | doctrine 1항(절단은 명시 지시 시만) + 기존 판정("분할 = 시간 2배, 각 편 약화") |

**마음이 바뀔 조건**: C1의 작동영역이 너무 좁아서(현실적 λ 범위에 비손실 구간이 거의 없어서) C2를 얹을 자리가 없을 때. 그때는 C1만으로 짧게 내고 C2를 다음으로 미룬다.

**§6의 헤드라인 수치**: 동일 `N`에서 `NET_CAPTURE`율 — 그리고 **동일 포획률에서의 limiter 접촉 수**. 후자가 더 좋다. *"학습된 팀은 덜 부딪히고 더 잡는다"* 는 한 문장이 곧 조향의 정의이기 때문이다.

## 6. `docs/27` 사다리 개정

축이 셋이 되지만 역할이 다르다.

```
λ           손실 회피 (반발 크기 + 예견 거리를 함께 스케일)
            현행 = ∞·예견0.  ->  sweep 축.  λ=0 = 음성 대조
행동 등급    A1 / A2 / A3      적응성 (jink · 편대 수준 라우팅 · baiting)
a_att       기민성             물리, 플랫폼 브래킷
```

**`route_gain` 재정의**: `docs/27` §2.3에서 "회피 능력"으로 뒀는데, 실은 **λ의 예견(anticipation) 성분**이다. 혼동을 막기 위해 분리한다.
- λ의 예견 성분 = 개별 살상구를 얼마나 미리 피하는가
- A2의 `route_gain` = **편대 전체의 배치를 보고 최대 간극으로 접근 방향을 잡는가** (개별 구가 아니라 formation 수준)

전자는 겁의 크기, 후자는 계획 능력이다. 둘을 섞으면 §5의 λ 축과 §6의 학습 주장이 교란된다.

### property 추가

| | property | 성격 |
|---|---|---|
| P1 / P1b / P2 / P3 | `docs/27` §5 그대로 | — |
| **P4** | **λ=0 에서 `NET_CAPTURE`율이 λ=∞ 대비 유의하게 낮아야 한다** | **강제** |
| **P5** | λ=∞ 에서 `limiter_contact` ≈ 0 이어야 한다 (겁먹는 공격자는 안 부딪힘) | 보고 |

P4가 C1의 기전을 증명하는 유일한 실험이다. 실패하면 *"조향이 아니라 차단이었다"* 로 판독하고 C1을 철회한다 — 결과를 보고 정하지 않기 위해 지금 적는다.
