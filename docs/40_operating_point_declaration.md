## 3. ★ 게이트가 잡아낸 것 (1) — 콘이 τ 와 어긋나 있었다

τ 를 0.15 로 내리자 `hold`/`ring`/`intercept` 가 **전부 24/24 NET_CAPTURE**,
최소거리 15.67 m 로 나왔습니다. 원인:

```
tau=0.15 s 에 네트가 실제로 간 거리 : 8.22 m
cone.range_max                      : 29.847 m   <- 3.6배
=> 네트가 닿을 수 없는 15 m 표적을 '포획'으로 판정했다
```

포획은 τ 시점에 판정되므로 콘의 축방향 밴드는 **τ 동안의 네트 병진**이어야 합니다.
`range_max = 8.22`, `half_angle = arctan(2.0/8.22) = 0.2387` 로 연동 수정했습니다.
폐로 정합도 맞습니다 — 발사 이격 11.22 m, τ 후 표적은 8.22 m = 네트 위치.

**이건 τ 선언의 필연적 귀결이고, PENDING 에 둘 항목이 아니었습니다.**

## 4. ★★ 게이트가 잡아낸 것 (2) — 콘을 고쳐도 조향 문제가 없다

수정 후 (12 에피소드, 스폰 랜덤화):

| 배치 | 라벨 | 저지 | 비손실 | 최소거리 |
|---|---|---:|---:|---:|
| **hold (무개입)** | NET_CAPTURE 12 | **1.00** | 1.00 | 5.62 |
| ring | NET_CAPTURE 10, CONTACT 2 | 1.00 | 1.00 | 5.47 |
| intercept | NET_CAPTURE 12 | 1.00 | 1.00 | 5.62 |

**limiter 가 아무것도 안 해도 finisher 혼자 전부 잡습니다. 조향 이득 = 0.00.**

### 4.1 명제 N 이 정확히 이걸 예측했다

`docs/10` 명제 N: `w = ½·a_att·τ²` 가 `ρ`(net radius) 이하이면
**무형상 방어가치가 0** — 조향 없이도 포획된다.

```
위협 상한 a_att = 78 에서도  w = 0.5 * 78 * 0.15^2 = 0.88 m  <  rho = 2.0 m
w >= rho 가 되려면 a_att >= 178 m/s^2 — 레이싱 FPV(137)보다도 위다
```

**즉 τ=0.15 에서는 현실적 위협 전 구간에서 조향이 불필요합니다.** 게이트 결과는
버그가 아니라 이론이 예측한 그대로입니다.

### 4.2 그래서 무엇이 드러났나

> **"협력 조향이 필요하다"는 논문의 전제는 `tau_deploy = 0.4` 위에 서 있었고,
> 그 0.4 는 근거가 없던 값이었습니다.** 근거를 찾아 고치자 전제가 무너졌습니다.

이것 자체가 심사에서 나왔을 지적입니다. 지금 발견한 것이 낫습니다.

## 5. 진단 — τ 를 우리가 과소 모델링했다

현재 τ 는 **네트 비행시간 하나**입니다. 실제 커밋-포획 지연은 그것만이 아닙니다.

```
tau_total = tau_sense + tau_decide + tau_slew + tau_flight
              ?            ?           ?         0.15   <- 우리가 모델링한 유일한 항
```

문헌이 나머지에 값을 줍니다 (전부 이미 확보한 출처):

| 항 | 값 | 출처 |
|---|---|---|
| `tau_sense` | **0.10 s** (LiDAR 10 Hz 1주기) | Pliska RA-L / Drones 10(6):420 |
| ↳ 카메라 경로면 | 0.20 s (5 Hz) | Drones 10(6):420 |
| `tau_decide` | dt = 0.05 s (결정루프 1틱) | 우리 규약 |
| `tau_slew` | 지향 오차 / ω=2 rad/s | Pliska. 오차 의존 |
| `tau_flight` | **0.15 s** | Xu 개방 + 폐로 기하 |

**`tau_sense + tau_decide + tau_flight` 만 더해도 0.30 s** 이고,
그러면 `w = 0.5·78·0.30² = 3.51 m > ρ = 2.0` — **조향이 다시 필요해집니다.**

### 5.1 그런데 이 방향은 우리에게 유리하다 — 그래서 조심해야 한다

τ 를 키우면 전제가 되살아납니다. **결과를 보고 값을 올리는 것으로 보일 수 있습니다.**

방어 논리는 이렇습니다:
- τ 를 "네트 비행시간"으로만 본 것이 **애초에 under-modeling** 이었습니다.
  `params.py` 는 τ 를 *"net deploy delay"* 라고만 적어 두었지 분해한 적이 없습니다.
- 추가 항은 **전부 외부 문헌 값**이고, 우리가 고를 수 있는 자유도가 아닙니다.
- 분해는 **결과와 무관하게 물리적으로 옳습니다** — 센서가 10 Hz면 표적 위치는
  커밋 시점에 최대 0.1 s 낡아 있습니다.

그래도 **이건 제가 단독으로 정할 사안이 아닙니다.** 되살리는 방향이라 Hyunjun 확인이 필요합니다.

### 5.2 대안 갈래

```
(가) tau 를 분해해 재선언        0.15 -> ~0.30. 각 항이 문헌 앵커. 전제 복원
(나) tau=0.15 유지하고 결론 수용  "이 체계에서는 단일 finisher 로 충분하다" 가 결과.
                                 논문은 '왜 조향이 불필요해지는가'의 경계 조건 논문이 된다
(다) 위협을 더 어렵게             a_att >= 178 이 필요한데 실재 플랫폼이 없다. **불가**
```

**(다)는 물리적으로 닫혔습니다.** (가)와 (나) 중 하나입니다.
개인적으로는 (가)가 옳다고 봅니다 — τ 분해는 결과와 무관하게 맞는 모델링이고,
(나)는 "센싱 지연을 무시했을 때"라는 단서를 달아야 하는데 그건 심사에서 바로 깨집니다.

## 8. ★ 해소 — τ 분해 재선언 (갈래 가 채택)

```
tau_total = tau_flight + tau_sense + tau_decide
          =    0.15    +   0.10    +   0.05     = 0.30 s      (6틱 정확, 격자 위)

  flight  Xu Fig.6 개방 0.13 s + 폐로 기하, dt 격자 반올림
  sense   LiDAR 10 Hz 1주기 -- Pliska RA-L / Drones 10(6):420.
          커밋 시점에 표적 위치가 이만큼 낡아 있다 (결과와 무관하게 참)
  decide  결정루프 1틱
```

**제외한 항** — 전부 τ 를 **키우는** 방향이므로 **0.30 은 하한**입니다:
`tau_slew`(지향오차/ω, 상태 의존이라 상수 불가), 카메라 경로(5 Hz → sense 0.20).
self-serving 우려에 대한 방어는 이 비대칭입니다 — **우리에게 유리한 항을 빼고도 전제가 복원됩니다.**

`range_max` 는 **8.22 m 그대로**입니다. sense/decide 지연은 발사 *전*에 일어나므로
네트 병진에 들어가지 않습니다. 폐로 정합: 이격 14.22 m, τ_total 후 표적 8.22 m = 네트 위치. ✓

### 8.1 뜻밖의 소득 — 브래킷이 명제 N 경계를 가로지른다

```
w = 0.5*a*tau^2 = rho  ->  a* = 2*2.0/0.30^2 = 44.4 m/s^2
위협 브래킷 [11, 78] 이 a* = 44.4 를 **가로지른다**

  a=11  w=0.49  조향 불필요        a=48  w=2.16  ★ 조향 필요
  a=30  w=1.35  조향 불필요        a=78  w=3.51  ★ 조향 필요
```

**한 브래킷 안에 두 regime 이 다 들어옵니다.** 정책이 위협 등급에 따라 다르게
행동해야 하고, 그게 §6 의 주장을 단일 regime 보다 훨씬 강하게 만듭니다.
**이건 맞춘 게 아니라 앵커 값에서 떨어져 나온 결과입니다** (P32 가 고정).

| **위협 랜덤화** | hold | 0.33 | — | |
