## 1. 철회

### 철회하는 문장 (2026-08-05, docs/51 후속 분석 및 대화 기록)

> "1.2 초 내 limiter 가 공격자 근처에 도달할 수 없으므로 **성형 채널이 구조적으로
> 무력하다.** 편대 학습이 실패한 게 아니라 편대 채널이 무력하다. PBRS 도 A3 도
> 이걸 안 바꾼다."

### 대체 문장

> 평가된 휴리스틱(`ring`·`intercept`·`brake`·`lam20`)은 성형 영향을 만들지
> 못했지만, `hold` 공격자 궤적을 기준으로 한 **낙관적 접촉 도달성 검사**에서는
> `SHAPING_NEEDED` 판의 **111/122** 에서 적어도 한 limiter 의 영향관 접근이
> 가능했다.

**무엇을 잘못했나.** 두 손설계 컨트롤러가 `hold` 와 같은 결과를 냈다는 사실에서
*"어떤 편대도 불가능하다"* 를 유도했다. 그건 정책류의 상한이 아니라 **선택한
컨트롤러 두 개의 실패**일 뿐이다. 그리고 근거로 든 *"종료 시 최근접 7.02 ≫
kill_radius 0.75"* 는 성형 전이법칙을 확인하지 않은 채 쓴 비교였다 -- 우연히
반경은 맞았지만(§2), 추론 자체는 법칙 확인 전에 이뤄졌다.

**규율.** 앞으로 "구조적으로 / 물리적으로 불가능" 은 **인증을 만든 뒤에만**
쓴다. 휴리스틱의 실패는 상한이 아니다.

### 1.2 ★ 철회 2 — "성공 = 모든 탈출구 봉쇄" 라는 해석

같은 날 단계 2 오라클을 설계하다가 **성공 술어 자체를 반대로 알고 있었음**을
발견했다. `min N_uncaught` 를 목적으로 잡으려 했는데, 그건 `boxed_in` 을 최적해로
뱉는 **틀린 문제**다.

> **철회**: "성형의 목표는 공격자의 탈출구를 막는 것이고, 전부 막으면 포획이다."
>
> **대체**: 성공은 **선택적 압축**이다 -- 원뿔 **밖** 탈출은 전부 제거하되
> 원뿔 **안** 탈출을 **하나 이상 남긴다.** 전부 막으면 `boxed_in` 이 되어
> **포획이 아니다.**

이 오해를 기록 없이 넘겼으면 오라클이 잘못된 목적함수를 "인증" 할 뻔했다.

## 2. 먼저 확인했어야 할 것 — 성형 전이법칙

`shepherd/game/viability.py::_feasible_limiter`:

```python
"""True iff the attacker parabola NEVER enters any limiter kill-radius over [0, tau]"""
pts  = x0 + v0*s + 0.5*accels*s²          # s in [0, tau], n_t=24 substeps
d    = ||pts − L||                        # L = limiter 위치들
hits = (d <= kill_radius).any()
return ~hits
```

```
성형 영향 반경  = kill_radius = 0.75      <- 하드킬 접촉 반경과 **같은 값**
지평            = tau_deploy = 0.3 s
사용하는 것     = limiter **위치만**
사용 안 하는 것 = limiter 속도 · 헤딩 · 압력비트
```

즉 성형은 "공격자가 다음 0.3 초에 지날 수 있는 곳으로부터 0.75 m 안에 몸을
두어 그 탈출 표본을 지우는 것" 이다. 원격장이 아니라 **근접 차폐**다.

### 2.1 ★ 부수 발견 — limiter 압력비트는 성형에 들어가지 않는다

정책의 limiter 행동은 `가속(3) + 비트(1)` 인데, 그 비트는

- `env.py` 백엔드 경로: `la[:3]` 만 사용. 비트 미사용
- `viability`: 위치만 사용. 비트 미사용
- **`env_sys.py:239`**: `if len(a) >= 4 and float(a[3]) > commit_threshold` ->
  **하드킬 커밋** 기록 (`CommitRecord`)

**죽은 차원은 아니다.** 그러나 **성형 채널에는 인과효과가 0** 이고, 오직
하드킬(= 논문 스파인을 깨는 경로)에만 연결된다. 행동 구조를 논할 때 이
비대칭을 먼저 적어야 한다: 정책이 가진 이산 자유도 하나가 **비손실 성형에는
아무 영향이 없고 파괴적 결말에만 영향을 준다.**

## 3. 감사 술어 (수식 고정)

```
c_i(t) = p_i(0) + v_i(0)·t                          도달가능구 중심
r_i(t) = ½ a_max t²                    (a_max·t <= v_max)
       = v_max·t − v_max²/(2 a_max)    (그 이후, 속도 상한 반영)

m_e = min           ( |p_att(s) − c_i(t)| − r_i(t) − r_shape )
     t, i, s∈[t,t+τ]

m_e <= 0   ->  접촉 가능
m_e >  0   ->  이 근사 아래 접촉 불가
```

단위는 m. `r_shape = kill_radius = 0.75`. `a_max = scn.limiter.a_max`,
`v_max = threat.v_lim`. 속도 상한 piecewise 를 **반드시** 적용한다 -- 단순
`½at²` 만 쓰면 포화 이후 도달집합을 과대평가한다.

재현: `python -m shepherd.scripts.contact_reachability --n 200
--out results/contact_reachability.json`

## 3.5 ★ 성공 술어 — 봉쇄가 아니라 선택적 압축

`viability._v_shot_with_accels` 실제 계산:

```
feasible = limiter 에 막히지 않은 탈출 표본        (kill_radius 근접 판정)
caught   = 그 표본의 종점이 finisher 원뿔 안        (se3_cone)
n_feasible == 0  ->  boxed_in = True, v_shot_soft = 1.0 로 보고되지만
                     이는 **연속성용 대리값**이고 clean net-shot 이 아니다 (R4 SPLIT)
포획 = (not boxed_in) and (v_shot_worst >= 1.0)
     = 살아남은 탈출이 1 개 이상 ∧ 그것들이 **전부** 원뿔 안
```

수식으로:

```
clean capture  <=>  N_bad,uncovered = 0   ∧   N_good,surviving >= 1
```

**틀린 목적함수**: `min N_feasible` (봉쇄). 이건 `boxed_in` 으로 수렴한다.

보조 목적을 넣는다면 **사전식 순서**를 이렇게 고정한다:

```
1. uncovered bad 최소화                    (0 이어야 함)
2. surviving good >= 1 강제                (제약. boxed_in 은 infeasible 처리)
3. bad 에 대한 coverage margin 최대화
4. surviving good 의 cone margin 최대화
5. 이동량 / 제어 effort 최소화
```

### 3.6 중간 기하와 최종 포획 기하는 다르다

*"`ring` 이라는 형상을 우리가 정해 둔 것 자체가 문제"* 라는 문제제기는 옳다.
다만 두 기하를 구분해야 한다 -- 안 하면 *"최종 술어가 원뿔인데 왜 원뿔을
무시하나"* 로 바로 반박당한다.

| | 무엇 | 고정되는가 |
|---|---|---|
| **중간 기하** | 공격자를 어디로 몰지, 누가 측면·누가 후방을 맡을지. 시간에 따라 전개되는 편대 형태 | **고정하지 않는다.** 반구·비대칭 벽·이동 차단면·순차 funnel 무엇이든 가능. 이것이 발견 대상 |
| **최종 포획 기하** | 발사 시점에 살아남은 탈출이 finisher 의 고정 원뿔 안 | **피할 수 없다.** 성공 술어 자체다 |

정확한 표현: **중간 편대 형상을 원뿔 모양으로 미리 고정하지 않는다. 다만 최종
잔여 도달가능집합은 발사 원뿔 안으로 압축되어야 한다.**

### 4.1 FREE(0.487) < SHAPING(0.910) 역전의 원인 — 라벨이 난도가 아니다

선언에 **결합**이 있다 (`params.py`):

```
physics.a_lim_max = 0.35 × physics.a_att_max        <- 파생 관계
```

`SHAPING_NEEDED` 는 `½·a_att·τ² > net_radius` 로 정의되므로 **a_att 가 큰 판**
이다. 그런데 a_lim 이 a_att 에 비례하니 limiter 가속도 같이 커진다.

```
SHAPING 판  a_att 중앙 58.0  ->  a_lim 20.29
FREE   판   a_att 중앙 26.2  ->  a_lim  9.17      (2.21 배 차이)
```

**따라서 `SHAPING_NEEDED` 라벨은 "성형이 필요한가" 를 나타내지 "성형하기
어려운가" 를 나타내지 않는다.** 오히려 접근은 더 쉽다. 이 라벨을 난도 축으로
읽어 온 곳이 있다면 전부 다시 봐야 한다.

> **논문 표현 주의.** SHAPING 구간 성능을 *"더 어려운 구간 성능"* 으로 부르면
> 공격받는다. 정확히는: *"regime 은 성형 필요성을 분류하지만 limiter 의 물리적
> 난도에 대해 단조인 축이 아니다 -- 공격자 가속과 limiter 가속이 함께
> 증가하기 때문이다."*

### 4.5 ★ `2a-E ✔` 가 뜻하는 것 — 매우 약한 필요조건이다

체크만 보고 *"선택적 압축이 가능하다"* 로 읽으면 안 된다. 논리량화자가 다르다:

```
2a (통과함)   ∀b ∈ B,  ∃i, ∃c_i ∈ R_i(T) :  c_i 가 b 를 제거
2b (미검)     ∃c_1..c_4 :  ∀b ∈ B, ∃i : c_i 가 b 를 제거
              ∧  ∃g ∈ G : ∀i, c_i 가 g 를 제거하지 않음
```

**개별적으로 가능한 위치들이 서로 완전히 다른 곳일 수 있다.** 2a 통과율이
높아도 2b 가 거의 0 일 수 있다.

지금 강하게 쓸 수 있는 문장은 여기까지다:

> 환경의 전체 union 을 기준으로도 SHAPING 19/23 은 모든 bad escape 가
> **개별적으로** limiter 도달권 안에 있었다. 따라서 **단일 escape 접근
> 불가능성은 그 19 판의 병목이 아니다.** 다음 관문은 네 개의 정적 limiter
> 위치가 모든 bad 를 **동시에** 제거하면서 good 하나를 보존할 수 있는지다.

## 5. 낙관성 (결론과 함께 인용할 것)

### 5.3 ★ 환경 술어 — limiter 는 전개 지연 동안 **정지**다

`_segments_endpoints_feasible:426-432` (그리고 `_feasible_limiter`):

```python
L = np.asarray(limiters, float).reshape(-1, 3)     # ★ 시간 인덱스가 없다
pts = np.concatenate(seg_pts, axis=1)              # 공격자 경로 (n, K*n_t, 3)
d = np.linalg.norm(pts[:, :, None, :] - L[None, None, :, :], axis=3)
feasible_lim = ~(d <= kill_radius).any(axis=(1, 2))
```

> env 는 전개 지연 동안 limiter 를 **움직이지 않는다.** 후보 발사 시각 `T` 의
> limiter 위치를 고정하고, 그 위치와 공격자 escape trajectory 의 **이산
> 경로점 전체**를 비교한다.

이것이 물리 현실에 정확한지와는 **별개**다. 그래서 두 술어를 분리한다:

```
2a-E  environment-faithful : 발사 시점 도달 가능한 **정적** 위치  대  이산 escape tube
2a-P  physical audit       : 전개 중 limiter 운동 포함, 같은 절대시각끼리, 연속 궤적
```

**2b 와 학습 결과 해석의 기준은 `2a-E` 다.** `2a-P` 는 별도 감사 항목이고,
연속시간 접촉은 이산 격자로 완전히 보장되지 않는다 (`d_cont >= d_samp − δ`,
δ = 인접 표본 최대 이동량/2 -- P77c).

### 8.7 2a-E 재정의 (union 기반 재실행)

후보 발사 시각 `T` 에서, 각 bad trajectory `b` 에 대해

```
∃ i :  min_p∈paths(b)  |p − c_i(T)|  <=  r_i(T) + r_shape        (c_i 는 **정적**)
```

★ `2a-P`(같은 절대시각·연속 궤적)로 바꾸지 **않는다** -- 그러면 환경이 풀지
않는 문제를 푸는 것이 된다 (§5.3).

블록별로 분해해 기록한다 -- 실패가 어느 extreme family 에서 오는지가 결론을
가른다:

```
n_good_by_block / n_bad_by_block / n_bad_coverable_by_block
n_bad_unreachable_by_block / worst_reach_slack_by_block
best_step / pass_2a_union     + Block 1 만의 값도 같이 저장
Δ_extreme = N_unreachable,union − N_unreachable,Block1
```

**Block 3(dogleg)이 병목일 때의 해석 주의.** 말할 수 있는 것은
*"환경의 clean-shot 판정이 Block 3 dogleg extreme 에 지배된다"* 까지다.
그것이 과도한 보수성인지 실제 robustness 요구인지는 별개 문제이며, 다음을
갈라야 한다:

```
dogleg 가 실제 A2 의 가속·선회 능력 안  -> 실제로 막아야 하는 유효한 탈출
실제 폐루프 동역학에서 구현 불가능       -> S14 fidelity 문제
극점 각각은 가능하나 한 공격자가 그 시퀀스를 실행 못 함 -> union 의 시간적 결합 문제
```

감사 방법: **unreachable dogleg witness 를 실제 공격자 동역학에 replay** 해 본다.

### 8.1c ★ witness 여유 감사 — **둘 다 1.5~2 cm knife-edge** (2026-08-06)

도달성이 아니라 **선택적 압축의 기하적 정밀도**다.

각 300 회):

| 반경 | ep9 clean | 덜막음 | 너무막음 | ep30 clean | 덜막음 | 너무막음 |
|---|---:|---:|---:|---:|---:|---:|
| ±0.01 m | 1.000 | 0.000 | 0.000 | 1.000 | 0.000 | 0.000 |

**실패가 양쪽으로 갈린다** -- 덜 막아서(uncovered bad)와 너무 막아서(boxed_in)가
비슷한 비율이다. (★ 2026-08-06 정정: `boxed_in` 을 **임무 실패**라고 부른 것은
보류한다. 그건 clean net capture 가 아닌 것은 맞지만, 접촉 event resolver 가
없어서 실제로 무엇인지 미확정이다 -- docs/53 §4.3~4.4.) witness 가 두 실패 모드 **사이의 좁은 띠**에 있다는 직접

(±0.05 에서 0.78 vs 0.43, 그리고 boxed 쪽 실패가 0) **정도의 차이**다.

**발사 시각은 정확히 한 tick 이다** (재최적화 없이 replay):

```
ep9    t−1 uncovered_bad(378)   t clean(1)    t+1 boxed_in(0)
ep30   t−1 uncovered_bad(774)   t clean(26)   t+1 boxed_in(0)
```

한 스텝(50 ms) 이르면 아직 못 막고, 한 스텝 늦으면 **다 막아 버려** boxed 다.

> ★ **표현 제한.** 이건 `t` 에서 최적화한 **같은 위치를 그대로 옮겨** 평가한
> 것이다. 시각마다 다시 최적화하거나 움직이는 limiter 궤적이 경계를 따라가면
> clean corridor 가 더 길 수 있다. 정확히는:
>
> > 현재 두 snapshot witness 는 **고정 배치 기준으로** 1-tick temporal support
> > 만 보였다. 시각별 재최적화나 실행 가능한 궤적에서도 corridor 가 1 tick
> > 인지는 **미검증**이다.
>
> 두 층을 분리해 기록한다: **고정 배치 support**(측정함) vs
> **시각별 재최적화 support**(미검). 후자가 있어야
> *"clean snapshot 이 한 tick 만 존재"* / *"여러 tick 존재하나 위치가 빠르게
> 이동"* / *"solver 가 특정 tick 만 찾음"* 이 갈린다.

### 8.1c-1 이것이 단계 3 에 뜻하는 것

시간 일관 궤적(단계 3)은 이 좁은 띠를 **정확한 순간에** 통과해야 한다. 그리고
polling 이 아니라 **한 tick 안에** 도달해야 한다. 그래서 단계 3 의 첫 대상은
**ep30 처럼 여유가 상대적으로 큰 witness** 로 한다 -- ep9(m_good 1.4 cm,
boxed 쪽 실패 0.267)부터 시도하면 시간 일관성 실패와 이산 경계 취약성이 섞여
다시 해석 불능이 된다. **ep9 는 경계 사례로 보존한다.**

### 8.1d ★ SHAPING 19 판 확장 — witness 8/19, **전부 knife-edge** (2026-08-06)

디버그 2 판은 선택 편향이 있으므로 prevalence 감사는 **여기서부터**다.

### 8.1e ★ 시각별 재최적화 — corridor 는 **이동하지 않는다. 흩어져 있다** (ep18)

§8.1c 의 "고정 배치 1 tick" 이 (1) *snapshot 이 50 ms 만 존재* 인지
(2) *여러 tick 존재하나 배치가 이동* 인지 못 갈랐다. `t = 18..30` 에서
A(독립 재최적화)와 B(continuation, warm start + trust region 0.6 m)를 나눠 풀었다.

| t | A 독립 | m_sel | n_feasible | B continuation |
|---:|---|---:|---:|---|
| 18~20 | no_witness | — | — | — |
| 21 | **boxed** | — | — | — |
| 22~24 | no_witness | — | — | — |
| **25** | **clean** | +0.0022 | 14 | no_witness |
| **26** | **clean** | **+0.0197** | 2 | clean (시드) |
| 27 | uncovered_exact | — | — | no_witness |
| **28** | **clean** | +0.0067 | 1 | — |
| 29~30 | uncovered_exact | — | — | — |

```
exact support        {25, 26, 28}     <- 흩어져 있다. 연속 아님
최장 연속            2 tick = 0.10 s
robust support       m_sel >= 0     3 tick
                     m_sel >= 0.01  1 tick   (t=26 뿐)
                     m_sel >= 0.02  0 tick   ★
```

**B(continuation)는 양방향 모두 끊긴다.** t=26 에서 출발해 27 로도 25 로도
trust region 0.6 m 안에서 해를 못 찾는다. 독립해는 25·26·28 에 있는데
**서로 0.6 m 안에 있지 않다.**

인접 독립해 사이 배치 이동량:

```
t=25 -> 26   [1.099, 0.804, 1.218, 2.545] m
             필요속도 [22.0, 16.1, 24.4, 50.9] m/s     v_max = 25.9
             ★ 4 기 중 1 기가 v_max 를 2 배 가까이 초과
```

**판정 (리뷰어 분기표의 "독립 성공 / continuation 실패"):**

> clean snapshot 은 여러 시각에 존재하지만, **발견된 해들이 동적으로 연결되는지는
> 불분명하다.** 단계 3 에서 **연결 최적화가 핵심 병목**이다.

정확히 제한하면: `t=25 -> 26` 의 **그 해 쌍**은 v_max 를 넘으므로 연결 불가다.
그러나 이는 *"연결 가능한 해 쌍이 존재하지 않는다"* 의 증명이 아니다 --
독립 최적화는 가까운 해를 고를 유인이 없고, trust region 0.6 m 도 한 값일 뿐이다.

### 8.1e-1 ★ solver 가 시드에 민감하다 — 직접 확인

**같은 ep18·같은 t=24 인데 이번엔 `no_witness` 다.** §8.1d 의 19 판 런에서는
그 tick 에서 `m_sel = +0.0230` 인 witness 를 찾았다. **차이는 난수 시드뿐이다.**

이건 §8.1d-1 의 *"`NO_WITNESS_WITHIN_BUDGET` 은 불가능이 아니다"* 를 추측이
아니라 **실측으로** 확정한다. 동시에 위 표의 `no_witness` 칸들도 같은 지위다 --
support 집합 {25,26,28} 은 **하한**이고, 실제 support 는 더 넓을 수 있다.

따라서 **multi-seed 없이 support 폭을 결론내지 않는다.** 다음 실행부터
tick 당 최소 3 시드를 돌린다.

### 8.2 2b 가 답하는 질문과 **답하지 않는 질문**

각 후보 발사 시각 `t` 에서, 탈출 표본 `j` 의 궤적을 `x_j(s)`, limiter `i` 의
배치를 `c_i ∈ R_i(t)` 라 하면

```
h_ij(c_i) = 1[ min_{s∈[0,τ]} |x_j(s) − c_i| <= 0.75 ]

feasible  <=>  ∀ j ∈ B_t : max_i h_ij = 1        (모든 bad 를 덮는다)
           ∧   ∃ j ∈ G_t : max_i h_ij = 0        (good 하나는 남긴다)
```

**2b 실패가 말하는 것** — `hold` 공격자 궤적의 검사된 후보 시점에서는 실행
가능한 최종 snapshot 을 **찾지 못했다.** 그뿐이다.

**2b 실패가 말하지 않는 것** — *"현 시나리오에서 어떤 능동적 협력 정책도
성공할 수 없다."* 능동적 성형은 공격자의 미래 상태와 그때의 good/bad 분할
**자체를 바꾼다.** `hold` 궤적에는 다음이 통째로 빠져 있다:

```
limiter 행동으로 공격자 궤적이 바뀌는 효과
초기에 일부 탈출을 열어 두었다가 나중에 닫는 전략
공격자를 더 유리한 상태·방향으로 유도하는 장기 효과
limiter 역할 교대 · 반구 표면 추종 같은 폐루프 전략
hold 궤적에는 존재하지 않는 새로운 발사 기회
```

**2b 성공이 말하는 것** — `hold` 궤적에서도 최종 clean-shot snapshot 이
물리적으로 존재한다. 그러면 병목은 **그 snapshot 까지의 시간 일관 궤적** 또는
학습 문제로 넘어간다. (이쪽이 더 강한 진술이다.)

**2b 의 첫 목적은 성공 witness 찾기다. 실패 인증은 별도 과제**이고, 이산화
오차 상한이나 branch-and-bound 가 추가로 필요하다. 해를 못 찾은 것을 불가능이라
부르지 않는다 -- 이 문서가 철회한 것과 **같은 종류의 오류**다.

### 8.3 ★ 단계 3 — 형상을 고정하지 않는 궤적 오라클

2b 다음의 핵심은 snapshot 집합덮개가 아니라 **full-trajectory oracle** 이다.
결정변수는 `ring` 의 반경이나 formation shape 가 **아니라 각 limiter 의
가속열** `u_i(0..T−1)` 이고, 공격자는 실제 A2 반응법칙으로 매 스텝 갱신한다.
발사 시각도 변수다.

그래야 optimizer 가 반구 추종·후방 차단·일시적 비대칭 funnel·2 기만 핵심
차단·역할 교대·회피 유도 후 반대쪽 폐쇄 중 **무엇이든 고를 수 있다.**
기하를 결정변수로 정하지 말고 **제어열을 결정변수로 두고 결과 기하가 나오게**
한다. 이것이 "최적 기하를 모른다" 는 문제의 올바른 오라클이다.

차원이 크면 20 Hz 가속을 전부 최적화하지 말고 limiter 당 4~6 개
piecewise-constant macrosegment 로 시작한다 -- **옵션을 미리 규정하는 것이
아니라 수치 최적화를 위한 시간 압축**이다.

### 8.4 ★ 보상 계약이 능동적 기하를 억제할 수 있다

`Δv_shot` 은 **현재 순간의** limiter 위치로 0.3 초 탈출 집합을 평가한다.
따라서 반구 표면을 선점하려고 어떤 limiter 가 잠시 현재 탈출관에서 멀어지면

```
장기적으로는 더 좋은 funnel 을 만들지만
당장 v_shot 은 떨어지고
정책은 음의 보상을 받는다
```

**"조밀 보상이 있다" 와 "올바른 장기 기하를 가리킨다" 는 다르다.**

단계 3 에서 witness 궤적을 찾으면 그 궤적을 따라 `Δv_shot` · uncovered bad ·
surviving good · clean margin · limiter 별 counterfactual 기여를 **그려야
한다.** 성공 궤적에서도 `Δv_shot` 이 대부분 0 이거나 중간에 음수라면, 현재
보상은 능동적 기하를 발견하는 학습 신호가 아니고 **보상 계약과 연구 목표가
충돌**하는 것이다.

### 8.5 RL 의 정당화 — 정확한 형태

*"최적 기하를 모르니까 RL"* 은 방어가 약하다. MPC 나 trajectory optimization 도
모르는 기하를 찾는다. 정확한 형태는:

> 오라클 최적화는 **성공 회랑의 존재와 구조를 확인하는 분석 도구**다 (가능성
> 증명 · 강한 기준선 · teacher). 실제 임무에서는 반응형 공격자에 대해 매 스텝
> 다중 에이전트가 **폐루프**로 대응해야 하고, 반복 최적화의 계산비용과 상태
> 변화 때문에 **학습된 정책**이 필요하다.
>
> 즉 "기하를 모르기 때문에 RL" 이 아니라, **"기하를 미리 고정하지 않은 폐루프
> 정책이 필요하고, 오라클은 그 정책류가 성공할 수 있는지를 먼저 확인한다."**

### 8.6 행동 파라미터화 — 현재 판정

스텝별 3D 가속이 **표현력상** 부족하다는 주장은 아직 지지되지 않는다. 반구
추종이든 후방 차단이든 결국 3D 가속열로 구현된다. 옵션·스킬·관계적 행동은
새로운 물리 궤적을 **가능하게** 하기보다 그 궤적을 **찾기 쉽게** 만드는
inductive bias 다.

가르는 검사:

```
low-level 궤적 최적화가 성공  ∧  그 가속열을 BC 가 재현  ∧  RL 만 실패
    -> low-level 행동은 충분. 병목은 탐색·보상·credit
궤적 최적화도 거의 못 찾는데 고수준 waypoint/차단점 변수로는 찾음
    -> 행동 추상화가 실질적 병목
```
