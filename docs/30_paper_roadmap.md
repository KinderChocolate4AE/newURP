## 0. 오늘 데이터가 바꾼 것

`rho_v` 밴드 확인(50셀)이 준 세 줄:

```
정적 shaping(ring)   전 격자 0저지 (0/24)  -- 능력비 문제가 아니라 구조 문제
저지 13/50           전부 HARD_KILL
NET_CAPTURE          0        <- 한 번도 열린 적 없음
```

⇒ **C1(비손실 격추가 성립한다)의 증거가 현재 0개이고, 시스템은 "그냥 자폭이 답"이라고 말하고 있다.**

이 상태로 학습을 돌리면 정책은 항상-하드킬로 수렴할 것이고, 그건 §5 사전 등록대로 *결과*이긴 하지만 **논문의 심장(§6 = 학습된 중재의 가치)이 비게 된다.** 중재할 선택지가 하나뿐이면 중재가 아니다.

## 1. 그래서 다음 실험은 하나로 압축된다

> **비손실 포획이 *무엇에 의해서든* 도달 가능한가?**

이걸 학습으로 답하면 서버 시간을 쓰고 몇 주 뒤에 알게 된다. **오프라인 탐색으로 먼저 답할 수 있다.**

```
ORACLE_ARBITRATION_UPPER_BOUND
  고정 시나리오에서 (limiter 배치 궤적 × 커밋 시점 × 발사 시점) 을
  오프라인 탐색해 도달 가능한 최선의 결과를 찾는다.
```

| 결과 | 함의 |
|---|---|
| oracle 이 `NET_CAPTURE` 를 만든다 | 도달 가능 → §5·§6 계획대로. 학습은 "찾을 수 있는가"의 문제로 축소 |
| oracle 도 못 만든다 | **어떤 학습도 못 만든다.** C1 은 경계 결과가 되고 논문이 갈래 B 로 |

**이것이 다음 블록이고, 나머지 전부가 여기에 의존한다.** `N*_oracle` 이 G5 를 미지 리스크에서 계산된 경계로 바꾼 것과 같은 수법이다.

### 1.1 같은 블록에서 함께 — 명제 N(b) lobe-mask

ring 이 실패하는 이유는 boxing 이고, **명제 N(b) 구성은 그것을 구조적으로 피한다**(core 를 남겨 `p_feasible = 1/12 > 0`). 이론이 "된다"고 말하는 유일한 정적 배치이므로, oracle 과 함께 돌려서 *"이론이 맞나"* 를 직접 본다. 지금 static baseline 이 straw man 인 것도 여기서 해소된다.

### 1.2 사전 등록 — `boxed_in` 이차 종점 (결과 보기 전 선언)

동결 포획 규칙(`env.py` L319):
```python
_pending_capture = (not boxed_in) and v_shot_worst >= 1.0
```
`boxed_in`(= `p_feasible == 0`) 을 제외하는 이유는 M2 의 판단이었다: *"limiter 가 가둔 것이지 네트가 잡은 게 아니다."* 당시엔 **위협과 접촉을 구분할 방법이 없었다.**

M4 는 그 구분자를 직접 갖는다 — **에피소드 수준 접촉 집합**. 따라서:

```
1차 종점(동결·보수)   captured = (not boxed_in) and worst>=1        <- 규칙 무수정
2차 종점(선언)        captured_relaxed = (worst>=1) and contact==0   <- 지금 선언
```

**둘 다 보고한다.** 불일치 자체가 M2 라벨링에 대한 발견이다. `env.py` 는 건드리지 않는다 — 2차 종점은 래퍼에서 관측만 한다.

> 이것을 **지금** 적는 이유: 나중에 `NET_CAPTURE = 0` 을 보고 나서 규칙을 완화하면 그건 소급 변경이다. 결과 전에 선언하면 이차 종점이다.

## 3. 아직 설계되지 않은 것 — M4 보상 (§6 의 숨은 전제)

**이게 로드맵의 가장 큰 구멍이다.** 현행 보상은 M2/M3 것이고 하드킬을 모른다.

```
J_M4 = w_int · 침투저지
     - w_kill · (하드킬 사용)          <- "비손실이 얼마나 값어치 있나"
     - w_pen  · 침투
     - w_waste · 낭비 발사
```

`w_kill` 이 **핵심 노브**다. 크면 정책이 포획을 선호하고, 작으면 자폭한다.
⇒ **`w_kill` 은 선언된 sweep 축이어야 한다.** 논문의 결과는 *"w_kill 을 이렇게 잡았더니 잘 되더라"* 가 아니라 **"w_kill 이 X 이상일 때 학습 정책이 영역 Y 에서 비손실 해를 찾는다"** 이다. 그 경계가 기여다.

주의: 기존 체크포인트는 커밋 비트가 무효이던 시절에 학습됐다. **§6 은 재학습 없이는 성립하지 않는다.**

## 4. 두 갈래 — §1 결과에 따라

### 갈래 A — oracle 이 `NET_CAPTURE` 를 만든다 (기존 계획)
```
C1  비손실은 (λ, Pk, rho_v) 의 유계 영역에서 성립한다
C2  학습된 중재가 같은 침투 저지율에서 더 높은 비손실 비율을 낸다
헤드라인  동일 저지율에서의 limiter 접촉 수 / 하드킬 소모
```

### 갈래 B — oracle 도 못 만든다
```
C1' 이 regime 에서 비손실 포획은 도달 불가능하며, 그 경계는 (τ_deploy, ρ, r_kill) 로 결정된다
C2' 학습된 중재는 같은 침투 저지율을 **더 적은 limiter 소모**로 달성한다  (자원 효율)
헤드라인  저지율 대비 소모 자원 -- exchange frontier 의 축소판
```

**갈래 B 도 논문이 된다.** 헤드라인이 약해질 뿐이고, 메모의 exchange-economics 서사와는 오히려 더 가깝다. 그리고 §5 의 *"어디서 안 되는가"* 지도는 갈래 B 에서 오히려 중심 결과가 된다.

**둘 중 어느 쪽이든 §6 은 필요하다** — 학습이 무언가에서 이겨야 MARL 논문이다.

## 5. 임계 경로와 병목

```
[지금] oracle + N(b)         반나절~하루   <- 갈래 결정
   ↓
       M4 보상 설계           반나절
   ↓
       (λ × Pk) sweep         하루          §5 Fig 1
   ↓
       재학습 런북 준비        반나절
   ↓
[서버] 재학습                 며칠          <- 최대 병목, Hyunjun 실행
   ↓
       §6 평가 + §7 기전       하루
   ↓
       A3 + §8                이틀
```

**병목은 서버 재학습 하나다.** 그 앞의 모든 것은 샌드박스에서 끝난다.
⇒ **재학습 런북을 sweep 과 병렬로 준비**해서 서버가 놀지 않게 한다.
