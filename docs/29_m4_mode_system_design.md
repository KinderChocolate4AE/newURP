## 1. 왜 필요한가 — 현 모델의 비정합

`env.py` L353: limiter 살상반경은 **비용만 발생시키고 아무도 죽이지 않는다** (S1 비준: *cost-bearing shaping pressure, NOT a consumable missile*). 그런데 `adversary.py`의 공격자는 그것을 **전권한 이상으로 회피하도록 하드코딩**돼 있다.

> **모델 안에서 실제로 위험하지 않은 것을 공격자가 무서워한다고 가정하고 있다.** 단순화가 아니라 비정합이다. 합리적 공격자는 그냥 통과한다 — 그리고 실측에서 매 에피소드 limiter 2기 접촉 후 20/20 침투했다.

이것이 `λ`가 왜 가짜 파라미터였는지도 설명한다. 무서워할 대상이 없으니 무서움을 손으로 넣을 수밖에 없었다. **위협이 유효해지면 λ는 파라미터가 아니라 기대값 계산의 결과로 창발한다.**

### 1.1 채점이 뒤집힌다

`clean_crossed = threshold_crossed AND NOT boxed_in` — 즉 **가둠이 실패로 채점**돼 있었다. 가둠이 치명적이면 가둠은 **성공**이다(파괴적일 뿐).

⇒ `clean crossing = 0`이 캠페인 내내 나온 이유는 **모든 성공 경로가 boxing을 통과하는데 boxing이 성공이 아니라고 정의돼 있었기 때문**이다. 이는 실패가 아니라 **모드 없는 시스템의 필연**이다. 캠페인 이력 전체가 이 관점에서 재해석된다.

## 2. 효과기 통일 형식

두 효과기가 **같은 형식**이다: 커밋 → 지연 τ 동안 공격자 회피 → 도달집합이 유효 체적 안이면 성공.

```
            τ        유효반경     w = ½·a_att·τ²      판정
네트      0.4 s      ρ = 2.0 m      2.40 m          FAIL  (w > ρ)
자폭      0.1 s      r = 2.0 m      0.15 m          OK    (여유 13배)
```

`w ∝ τ²` 이므로 **전개 지연이 짧다는 것 하나가 전부**다. 네트는 펼쳐져야 하고 탄두는 그냥 터진다.
교차점 `τ* = √(2r/a) = 0.365 s` — 그보다 빠르면 하드킬은 기하적으로 쉽다.

> **모드의 존재 이유가 이론에서 나온다.** 하드킬이 폴백인 것은 임의 설계가 아니라 `τ_kill ≪ τ_deploy`의 귀결이다. 명제 N이 그대로 확장되고, 논문은 효과기 둘을 **하나의 형식**으로 쓴다.

### 2.1 하드킬 기하 조건 (보수적 worst-case)

리미터도 τ_kill 동안 기동할 수 있으므로 추격 문제가 된다. 리미터는 예측점 쪽으로, 공격자는 반대로 최대 가속:

```
r = p_att − p_lim,  v = v_att − v_lim          (커밋 시점)
d_nom = |r + v·τ_kill|                          (명목 τ 후 상대거리)

기하 조건:  d_nom  ≤  r_kill + ½·(a_lim − a_att)·τ_kill²
격추:       기하 조건  ∧  Bernoulli(Pk)
```

`a_lim = a_att` 이면 여유항이 사라져 `d_nom ≤ r_kill` 로 퇴화한다(현행값). **기민성 비 `a_lim/a_att` 가 의미 있는 축이 된다**:

| a_lim | τ_kill | 유효 요격반경 | 여유 |
|---:|---:|---:|---:|
| 30 | 0.1 / 0.2 | 2.000 | +0.000 |
| 45 | 0.1 | 2.075 | +0.075 |
| 45 | 0.2 | 2.300 | +0.300 |
| 60 | 0.2 | 2.600 | +0.600 |

## 3. 모드는 구현하지 않는다 — 연속 제어 + 이산 비가역 방아쇠 (개정 v3)

> Hyunjun: *"mode가 굳이 이산적일 필요 있나?"*

**"모드"는 프레이밍이었지 필요한 기전이 아니다.** 시스템에 실제로 있는 것을 세면:

```
limiter    연속 가속 3차원  +  이산 커밋 비트 1개
finisher   연속 포인팅 3차원 +  이산 발사 비트 1개
```

위치 제어는 **이미 전부 연속**이고, 이산인 것은 **되돌릴 수 없는 마지막 방아쇠 하나**뿐이다.
그건 물리적으로 진짜 이산이다 — 탄두는 절반만 터지지 않는다.

| | 판정 |
|---|---|
| 모드 = **상태기계**(SHAPE/HARD_KILL 상태 + 전이 조건) | **삭제** |
| 방아쇠 = **이산**(이 limiter 가 지금 커밋한다) | **유지** |

상태기계를 삭제하는 이유가 결정적이다: **전이 조건을 손으로 짜는 순간, 학습시키려던 바로 그 중재를 스크립트로 되돌린다.** `if dist < X and v > Y then detonate` 를 피하려고 모드를 도입해놓고 모드 전이에 같은 것을 넣는 셈이다.

⇒ **모드 변수를 두지 않는다.** 시스템의 *거동*은 모드를 보이지만 *구현*에는 모드가 없다.
그래서 **"어떤 모드가 창발했고 언제 전환했는가"가 설계 입력이 아니라 §7 기전 분석의 결과**가 된다.

### 3.0 방아쇠 = 학습 제안 + env 가드 거부권 (리포의 기존 패턴)

연속 정책 안의 이산·비가역 행동은 학습이 어렵다(희소·미분 불가·고분산). **이 프로젝트는 이미 겪었다** — `J1 learned-fire 실패`, 학습 발사 방아쇠가 규칙 기반 brake 에 졌다(`.858` vs `.775`). 지휘 원칙도 *"shot 은 learned 필수 아님, rule-based terminal guard 분리가 더 자연·안정, hybrid = 원 문제를 더 적절하게 푸는 설계"* 로 정리돼 있다.

해법은 **리포에 이미 있는 패턴**이다. 네트는 지금도 정책이 발사를 *제안*하고 FSM 게이트(`v_shot ≥ θ_fire`)가 *거부권*을 갖는다. limiter 커밋도 같은 구조:

```
정책이 커밋 제안 (연속 로짓 -> 임계)
   ↓
env 가드 거부권
     기하 조건 불가        -> 거부
     R_nk 안에서 해소      -> 거부 (limiter 미소모)
```

학습되는 것은 **제안 타이밍**이고 그것이 곧 중재다. 새 설계가 아니라 승인된 hybrid 구조의 두 번째 적용이다.

**폴백 사전 등록**: limiter 커밋 학습이 J1 처럼 실패하면 규칙 기반 커밋 가드로 내리고 학습은 배치만 담당한다. **그 실패는 J1 과 같은 척도의 재확인이므로 결과로 성립한다.**

### 3.1 인터페이스 — 예약 차원이 정확히 이 자리다

limiter action 은 `Box(4)` = `accel(3) + pressure(1)`, 그리고 `params.py`:
```
"scripted.limiter_pressure": Param(1.0, "-", "RESERVED", "code-default",
    "Box(4) idx 3 -- env receives-and-ignores (reserved dim)")
```

**idx 3 = 하드킬 커밋 비트.** 이미 행동 공간에 있고, 이미 예약으로 문서화돼 있고, 범위도 `[0, 1]`이다.
`limiter_action[3] > 0.5` → 요격 커밋. **인터페이스 변경 0, 그리고 핸드오프가 처음부터 학습 가능한 차원이다.**

### 3.2 하드킬의 대가 (전부 시스템 안에서 지불)

```
파괴적       NET_CAPTURE 가 아니라 HARD_KILL 로 라벨. 잔해·부수피해·포렌식 상실
비가역 소모  성패와 무관하게 limiter 소진 -> 이후 shaping 용량 감소
확률적       Pk < 1. 실패해도 limiter 는 사라진다
```

소모된 limiter 는 **shaping 기여도 0** 이어야 한다. `v_shot` 이 env 내부에서 `lim_pos` 로 계산되므로, 백엔드 프록시(`env_adv`)에서 소진 limiter 를 선언된 far-field 주차점으로 이동시킨다. 모델링 선택으로 명시한다(은닉 금지).

## 4. 2층 지표

```
1차   침투 저지율               먼저 실제로 막아야 한다
2차   비손실 성공 비율          NET_CAPTURE / (NET_CAPTURE + HARD_KILL)
```

결과 라벨:
```
NET_CAPTURE    비손실 성공          <- 최선
HARD_KILL      파괴적 성공          <- 차선 (limiter 소모 + 부수피해)
PENETRATED     실패
SPENT_FAIL     수단 소진 후 미해결   (임무적 의미는 계속 보류)
TRUNCATED      우측 절단
```

**MARL 주장이 여기서 자연스러워진다**: 모드 중재는 스크립트로 짜기 어렵고 학습에 자연스럽다. 스크립트는 `if dist < X and v > Y then detonate` 같은 손튜닝 임계값이 필요하지만 학습 정책은 전체 상태에서 중재한다. *"limiter 를 더 잘 배치한다"* 보다 훨씬 강한 MARL 동기다.

**C2 재정의**: 학습된 중재는 **같은 침투 저지율에서 더 높은 비손실 비율**을 낸다 (또는 두 지표 모두 지배).

## 5. 축소 붕괴 — 인위적으로 막지 않는다

하드킬이 싸고 잘 되면 학습은 전부 자폭으로 수렴한다. **이것을 인위적으로 너프하지 않는다.**

이유: 2층 지표가 이미 처리한다. 항상 자폭 = 완벽한 침투 저지율 + 비손실 비율 0%. 그건 **정당한 작동점**이고, 논문의 질문은 *"조향이 침투 저지율을 희생하지 않고 비손실 성공을 사는가"* 이다.

**사전 등록** (결과 보기 전 기록):
> 학습 정책이 전 운용점에서 항상-하드킬로 수렴하면, 그것이 **결과**다 — *"이 영역에서 비손실 격추는 수지가 맞지 않는다."* 뒤집히는 경계(λ, Pk, a_att 평면 위)가 곧 기여이며, 사후 합리화가 되지 않도록 지금 적는다.

## 6. env 레인 — 서브클래스가 아니라 **env 래퍼**

하드킬은 **종료 규칙**을 바꾸므로 백엔드 프록시로는 부족하다(프록시는 env 가 반환하는 `terms` 를 못 바꾼다).

`env_m3` 식 서브클래스 + `step()` 163줄 복사는 다시 기각한다. 대신 **env 바깥에 래퍼**를 둔다:

```
shepherd/env_sys.py                      (NEW, non-frozen)
  class ModeSystemEnv:                   PettingZoo ParallelEnv 인터페이스 유지
      inner = ShapingParallelEnv         (동결, 무수정)
      step(actions):
          1. limiter action idx3 에서 커밋 비트 추출  (env 는 어차피 무시)
          2. inner.step(actions)  ->  obs, rew, terms, truncs, infos
          3. 커밋 타이머 진행 · τ_kill 만료분 가드 → 기하∧Pk 판정
             (모드 FSM 없음. limiter 별 커밋 타이머 + 해소 판정 + 가드뿐)
          4. 격추면 terms 를 True 로 덮고 outcome='HARD_KILL' 주입
          5. 소진 limiter 는 백엔드 프록시로 far-field 주차
```

층이 셋으로 깔끔하게 나뉜다:
```
env_sys.py     모드·종료          (래퍼)
env.py         물리·viability·FSM  (동결, 무수정)
env_adv.py     공격자 주입         (백엔드 프록시)
```
셋이 서로 다른 경계에서 작동하므로 조합된다. **지난 블록 산출물 4개 전부 그대로 재사용된다.**

## 10. 논문 정체 갱신

> **목표 지향 FPV 위협에 대한 완성된 last-mile 방어 시스템** — 비손실 네트 포획을 1차 수단으로, 파괴적 요격을 폴백으로 두고, 그 사이를 온라인으로 중재한다. 중재는 학습된다.

- **C1 (개념·기전)**: 비손실 격추는 λ>0 위에서 위협-조향으로 성립하고, 작동영역은 (λ, Pk, a_att)에서 유계다.
- **C2 (방법)**: 학습된 모드 중재는 같은 침투 저지율에서 더 높은 비손실 비율을 낸다.

인접 선행연구: 해군 AAW 의 hard-kill/soft-kill 협조(Blodgett/Laval-DRDC; Arslan NRL 2024)가 실재하나 **단일 사수·적 기동 shaping 없음**(메모 확인). ⇒ 우리 novelty = **협력 기동 shaping 이 소프트킬과 하드킬 사이의 결합자**라는 것. 모드 도입이 novelty 를 약화시키지 않고 오히려 위치를 선명하게 한다.

축소 붕괴    인위적 너프 금지. 항상-하드킬 수렴은 결과로 보고
동결 파일    env.py · adversary.py · falsifier · held-out 무수정 유지

## 12. 능력 비대칭 — 개정 (Hyunjun 2026-07-27)

§7은 limiter 능력을 다루지 않았다. 실사 결과 **현행값이 이종성을 무력화하고 있었다**:

```
limiter_v_max  80 m/s   vs  공격자 20~30 m/s   ->  2.7~4배 빠름
a_lim_max      30       =   a_att 30            ->  기민성 동등
                            (params.py 근거란: "fixture (= attacker authority)")
```

⇒ **현행 limiter는 공격자보다 우수한 요격기다.** 더 빠르고 똑같이 기민한 자폭체 4기가 있으면 네트는 당연히 군더더기다. 네트가 불필요해 보인 것은 설계의 진실이 아니라 **모델링 오류**다. `limiter_v_max = 80`(288 km/h)은 `docs/26 §3`에서 이미 비물리로 표시된 값이다.

### 12.1 기각된 안 — "추격 불가"

v_lim을 충분히 낮춰 추격 자체를 불가능하게 하는 안은 **기각**한다.

> Hyunjun: *"그럼 그냥 통발 피하면 되잖아."*

옳다. 정적 덫은 우회 가능하고, **A2의 편대 라우팅이 정확히 그것을 수행한다**(구현 완료). 게임이 자명해지고 방어가 무의미해진다.

### 12.2 채택 — 꼬리 추격 불가 · 선도 차단 가능

올바른 비대칭은 절대 속도가 아니라 **교전 기하**에 있다.

```
꼬리 추격   뒤에서 따라잡기          v_lim > v_att 필요    ->  불가능해야 한다
선도 차단   예측 교차점으로 선행      기하가 허락하면 가능   ->  가능해야 한다
```

느린 요격체도 리드 각이 있으면 빠른 표적을 요격할 수 있다. 못 하는 것은 **뒤에서 따라잡는 것**이다.
⇒ limiter의 임무는 추격이 아니라 **예측 차단**이며, 예측 차단은 반응이 아니라 선행이므로 협력 배치 문제가 된다.

### 12.3 이것이 협력을 필연으로 만든다

고전 추격-회피의 구조적 결과:

> **단일 저속 추격자는 고속 회피자를 포획할 수 없다. 다수의 저속 추격자는 협조하면 할 수 있다.**
> 필요한 수는 속도비가 낮아질수록 증가한다.

**협력은 편의가 아니라 저속 팀이 이기는 유일한 방법이다.** 지금까지 확보한 가장 강한 MARL 정당화이며, stipulation이 아니라 고전 문제 구조 위에 얹힌다.

우리 버전이 한 항을 더한다: **네트가 있으면 덮인 구멍을 남길 수 있으므로 더 적은 수로 된다.**

```
N*_with_net  <  N*_without_net        <- 이종성의 값어치. 측정 가능·반증 가능
```

네트는 limiter를 대체하는 것이 아니라 **구멍을 남겨도 되게 만들어 limiter 수를 줄인다.** 이것이 "귀찮게 네트를 왜 쓰나"의 답이고, `N*`가 헤드라인이 아니라 **이종성 페이오프의 척도**로 제자리를 찾는다.

### 12.4 파라미터 — 비율로 선언

| | 정의 | 현행 | 작업점 | 지위 |
|---|---|---:|---:|---|
| `rho_v` | `v_lim / v_att_max` | **2.67** | 0.7 | **선언된 sweep 축 (1순위)** |
| `rho_a` | `a_lim / a_att` | **1.0** | 0.7 | 선언된 sweep 축 (2순위) |

`rho_v`가 고전 추격-회피의 표준 파라미터이므로 1순위. 작업점: `v_att_max = 30` 기준 `v_lim = 21`, `a_att = 30` 기준 `a_lim = 21`.
**한 점을 고르지 않고 축으로 둔다** — 이종성이 성립하는 능력비 경계 자체가 결과가 된다.

### 12.5 "우회하면 되잖아"에 대한 답

덫은 정적이지 않다. limiter는 재배치한다 — 다만 공격자보다 느리므로 **반응이 아니라 예견**해야 한다. 공격자가 우회하면 거리·시간을 지불하고 다른 limiter 쪽으로 이동한다.
**공격자가 항상 자유 경로를 찾을 수 있는가**가 곧 `N*(rho_v)` 질문이고, N이 작으면 찾는다 — 그것이 결과다.

## 13. no-kinetic zone (이번 블록 채택)

자산 반경 `R_nk` 안에서는 **파괴적 요격 금지**. 잔해가 지키려는 것 위에 떨어지기 때문이며, 도심 last-mile에서는 실제 법적 제약이다.

```
R_nk 밖    limiter 격추 가능 (HARD_KILL)
R_nk 안    네트만 가능       (NET_CAPTURE)
```

### 13.1 왜 이것이 핵심인가

**공격자의 목표와 방어자의 제약이 기하적으로 결합된다.** 공격자가 가까워질수록 방어자의 선택지가 줄어든다 — 그리고 공격자는 정확히 그 방향으로 가려 한다.

핸드오프 결정이 진짜 어려워진다:

> **지금 죽일 수 있을 때 죽일 것인가, 들여보내고 비손실 포획을 시도할 것인가.**

이것이 학습할 가치가 있는 중재다. 손튜닝 임계값으로는 안 되고(상태가 다차원), 결정이 되돌릴 수 없으며(K=1·limiter 소모), 잘못 판단하면 침투다.

### 13.2 파라미터

| | 값 | 지위 | 근거 |
|---|---:|---|---|
| `R_nk` | 6.0 m | **ASSUMED, 선언** | 회랑 기하: finisher `x=2`, ring `x=8` — zone이 둘 사이에 놓여 외곽 회랑은 limiter가, 내부는 네트가 소유 |

민감도만 부수 보고한다(축을 늘리지 않는다).

### 13.3 규칙

```
R_nk 안에서의 하드킬 커밋은 거부된다 (관측 가능한 이벤트로 기록)
이미 커밋된 요격이 R_nk 안에서 해소되면 -> 거부, limiter 는 소모되지 않음
   (커밋 시점이 아니라 해소 시점 기준. 사전 확정)
```

### 13.4 property 추가

|---|---|---|

| **P12** | `rho_v < 1`에서 limiter가 꼬리 추격으로 접촉하는 사례가 없다 | 보고 |

## 15. M4 보상 (개정 v4) — 로드맵의 '최대 설계 구멍'

`docs/30 §3` 이 지목한 미설계 항목. 현행 보상은 M2/M3 것이라 하드킬을 모른다.
**물리 파라미터 근거와 완전히 무관하므로 앵커를 기다리지 않고 지금 확정할 수 있다.**

### 15.1 형태

```
J_M4 = dense_scale * J_env              기존 조밀 신호 (dv_shot + clean − waste − contact)
     + terminal_scale * TERMINAL        에피소드 종료 1회
     − c_lim * (소모된 limiter 수)

TERMINAL   NET_CAPTURE   +b_net
           HARD_KILL     +b_net*(1 − w_kill)
           PENETRATED    −c_pen
           TRUNCATED     −c_trunc
           SPENT_FAIL     0              (의미 감사 전까지 중립, docs/26)
```

**`w_kill` 이 유일한 핵심 노브이고 선언된 sweep 축이다.**
```
w_kill = 0   두 성공이 동등  -> 정책은 쉬운 쪽(하드킬)을 고른다
w_kill = 1   하드킬 보상 0   -> 소모 비용만 남아 비손실만 값어치
```
**그 사이 어디서 뒤집히는지가 결과다.** 값을 하나 골라 튜닝하면 그건 답을 정해놓고 실험하는 것이다.

### 15.2 세 가지 설계 결정

**① 보상과 지표를 분리한다.** 학습에서는 `TRUNCATED` 를 미격퇴로 벌하지만(지평선에서 공격자가 여전히 살아 접근 중), **보고 지표는 우측 절단(censored)으로 유지**한다. 둘을 억지로 맞추면 *"지평선이 짧아서 이긴 것처럼 보이는"* 산물이 생긴다.

**② 순서 불변식을 테스트로 강제한다.** 모든 `w_kill ∈ [0,1]` 에서
```
NET_CAPTURE >= HARD_KILL > PENETRATED = TRUNCATED
```
그리고 **limiter 를 전부 소모해도 하드킬이 침투보다 나아야 한다** — 안 그러면 정책이 "차라리 뚫리게 두는" 퇴화 해를 찾는다. `P13` 이 이것을 검사한다.

**③ 알려진 한계 — COMA 는 커밋 차원을 덮지 못한다.** 기존 `coma_D` 는 `v_shot_soft` 차분으로 계산되므로 **배치 차원에만 반대사실 credit 이 있다.** 커밋 차원은 정책 경사에만 의존한다.
⇒ `J1 learned-fire` 실패가 재현될 위험이 실재하며, 폴백(규칙 기반 커밋 가드 + 학습은 배치만)은 §3.0 에 사전 등록돼 있다. 커밋 차원 반대사실 확장(하드킬 유무로 임무 결과를 재계산)은 비용이 커 future work 로 둔다.

### 15.3 스케일

조밀항은 스텝당 `O(0.1~1)` 이 ~24 스텝 누적되고 종말항은 1회다. 그대로 두면 종말 신호가 묻힌다.
`terminal_scale = 10.0` 을 선언값으로 두되, **학습 전 스모크 체크로 두 항의 에피소드 누적 기여를 실측해 같은 자릿수인지 확인**한다(값을 결과 보고 조정하지 않기 위해 사전에 적는다).

### 15.4 기본값은 off

`RewardSpec.enabled = False` 가 기본이다. 그래야 기존 결과·`P6` bit-identical 이 보존되고, M4 보상은 명시적으로 켤 때만 적용된다. `P14` 가 passthrough 를 검사한다.

### 15.5 τ 도메인 랜덤화 (학습 설계)

τ 를 한 점에 고정해 학습하면 근거가 확정될 때 재학습해야 한다. 대신 **τ 를 에피소드별로 선언된 범위에서 추출**해 학습하면:
- 정책이 두 regime(네트 가능/불가능)을 모두 겪으므로 **모드 중재를 τ 의 함수로** 배운다 — 이는 곧 논문의 주장 그 자체다
- 나중에 τ 근거가 확정돼도 **재학습 없이 해당 구간을 보고**하면 된다

기존 `train/attacker_rand.py` 가 이미 config 딥카피 + 재구성 방식의 에피소드별 도메인 랜덤화 골격을 갖고 있어 그 경로를 확장한다.
