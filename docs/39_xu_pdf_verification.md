## 2. ★ `net_radius` 를 논문에서 직접 가져온다

### 2.1 역산 방법이 검증됐다

Eq.12: `C = exp((S^NP − S^UAV)/S^NP)` ⇒ `S^NP = S^UAV / (1 − ln C)`

Table 8 의 C 로 역산한 값을 **Table 3 의 직접 보고값과 대조**할 수 있습니다:

```
설계점 F = (25°, 50 m/s, 25 g) = Table 2 수준 (1,1,1) = Table 3 시험 #1
   Table 3 직접값        12.10 m^2
   Table 8 C 로 역산     12.10 m^2      <- 정확 일치
```

**역산은 추정이 아니라 논문 값의 재구성입니다.**

### 2.2 7개 설계점 전부

| sol | C (Table 8) | **S^NP 논문** | **r_net 논문** | r_net 우리 sim | 면적비 |
|---|---:|---:|---:|---:|---:|
| Baseline | 2.3174 | 12.53 | **1.997** | 1.998 | 1.00 ← 보정점 |
| **A** | 2.4802 | 21.82 | **2.635** | 2.423 | 1.18 |
| B | 2.4399 | 18.51 | **2.427** | 2.172 | 1.25 |
| C | 2.4359 | 18.23 | **2.409** | 1.981 | 1.48 |
| D\* | 2.4257 | 17.56 | **2.364** | 1.661 | **2.03** |
| E\* | 2.3904 | 15.56 | **2.225** | 1.680 | 1.75 |
| F | 2.3041 | 12.10 | **1.962** | 1.703 | 1.33 |

> **우리 시뮬은 baseline 을 제외한 전 설계점을 과소예측합니다 — 면적으로 최대 2.03배.**
> `net_forward.py` docstring 의 *"under-predicts the Table-3 spread"* 가 정량화된 값입니다.

### 2.3 그래서 무엇이 바뀌나 — 가정 그래프가 단순해진다

```
[이전]  A1(평가거리) -> rho_air -> { net_radius(교차검증), tau, range_max, half_angle }
[이후]  net_radius(7점) = 논문 직접값.  **A1 과 무관.**
        A1 -> rho_air -> { tau, range_max, half_angle }  만 남는다
```

**`net_radius` 는 이제 이 프로젝트에서 가장 강한 앵커입니다** — 논문 보고값이고,
역산 방법이 논문 자체 표로 검증됐고, 외부(Pliska 포획반경 2.0 m)와도 일치합니다.

### 2.4 포획 성립 판정 갱신 (docs/33 §3 대체)

`R_reach = ½·a_att·τ² ≤ r_net`, τ 는 우리 병진 시뮬(논문은 τ 를 보고하지 않음):

| sol | τ | r_net **논문** | 허용 a_att | (기존 sim r 기준) |
|---|---:|---:|---:|---:|
| Baseline | 0.398 | 1.997 | **25.2** | 25.2 |
| **A** | 0.253 | 2.635 | **82.3** | 75.7 |
| B | 0.337 | 2.427 | **42.7** | 38.2 |
| C | 0.402 | 2.409 | **29.8** | 24.5 |
| D\* | 0.505 | 2.364 | **18.5** | 13.0 |
| E\* | 0.501 | 2.225 | **17.7** | 13.4 |
| F | 0.496 | 1.962 | **16.0** | 13.8 |

교전거리 20 m 기준으로 **A 는 무장 FPV(48)를 여유 있게, 5인치(78)를 아슬하게** 덮습니다.
docs/34 §4 의 최적 발사창(τ≈0.13)으로 가면 이보다 훨씬 올라갑니다.

## 3. A1 판정 — 원문은 답하지 않는다

### 3.1 원문이 말하는 것

> §3.3.3: *"the effective interception area is defined as **the projection of the mesh surface
> on the plumb plane in the vertical direction of target movement**"*
>
> §4.1: *"**upon contact** between the flexible capture net and the UAV, the effective intercept
> area S^NP must be sufficient to encompass S^UAV"* ·
> *"the area over which the net is spread **as it nears the target location**"*
>
> §4.3 제약 g2 는 `S^E_(t)`, `S^NP_(t)` 로 **시간 인덱스**를 명시한다.

⇒ S^NP 는 **시간 의존 투영 면적이고 접촉 순간에 평가**된다. **그런데 그 순간에 해당하는
거리도 시각도 논문에 없습니다.** Table 3 의 125개 값이 어느 조건에서 읽혔는지 원문은
*"we obtained data on discrete points through simulation"* 라고만 씁니다.

### 3.2 판정

```
(a) 최대 면적(t≈0.13 s) 이다      -> 원문이 명시하지 않음. 다만 §3.3.2 는 "net spread area"
                                     를 최대 면적으로 **따로** 정의하므로 S^NP 와는 구별된다
(b) 특정 거리에서의 면적이다       -> 원문이 명시하지 않음
=> A1 은 원문으로 해소되지 않는다. engage_dist = 20 m 는 여전히 **우리 선택**이다.
```

**T1b 는 "확인하면 풀리는 문제"가 아니었습니다.** 논문에 답이 없습니다.

### 3.3 간접 증거는 (a) 쪽을 가리킨다 — 그리고 그게 우리에게 불리하다

발사각만 다른 세 설계점(v=50, m=25 g 고정, θ = D 45° / E 35° / F 25°)의 **순서**:

```
논문 :  F(1.962) < E(2.225) < D(2.364)     각도 클수록 면적 크다
우리 :  D(1.661) < E(1.680) < F(1.703)     각도 클수록 면적 작다   <- 완전 반전
```

물리적으로 **논문 쪽이 맞습니다** — 각을 크게 쏘면 블록이 넓게 퍼지니 개구가 큽니다.
우리 시뮬이 뒤집히는 이유는 **고정 거리에서 읽기 때문**입니다: 넓게 쏘면 전진이 느려
같은 거리에 도달할 때 이미 더 수축해 있습니다. 그 이동시간 페널티가 각도 효과를 덮습니다.

> **즉 "고정 거리 평가"라는 가정 자체가 논문의 config 의존성과 충돌합니다.**
> 논문이 고정 *시각*(최대 전개)에서 읽었다면 이 반전은 사라집니다.
> ⇒ **(a) 쪽 증거이고, 그렇다면 `rho_air` 는 20 m 까지 억지로 감쇠시키느라 과대 보정된 것이며
> 우리 τ 는 전부 과대추정입니다** (docs/34 §4.2-2 가 경고한 시나리오).

거리 적합으로 A1 을 역추정하려 했으나 **실패했습니다**: 7 m 에서 MAE 15.9%, 9 m 에서 25.5%,
어느 거리에서도 **순서가 맞지 않습니다.** 모델의 각도 의존성이 틀려서 거리 추정이 불가능합니다.

## 5. 남은 A1 — 이제 무엇을 해야 하나

논문이 답하지 않으므로 **선언**해야 합니다. 세 갈래:

```
(가) engage_dist = 20 m 유지        현행. 근거 없음. tau 0.253~0.505
(나) 최대 전개 시각(t=0.13 s) 채택   §3.3 간접 증거가 가리키는 쪽. tau = 0.13 고정
                                    r_net 은 논문값 그대로 쓸 수 있다(시각 무관하게 논문값)
(다) 폐로 기하로 대체               docs/35 §1.2 — tau 를 이격·접근속도의 함수로 푼다
```

**(다) 가 물리적으로 가장 정확하고 (나) 의 결론을 포함합니다.** 다만 `tau_deploy` 는 동결
`env.py` 의 FSM 타이머라 에피소드 상수로만 줄 수 있으므로, **(나)의 값을 (다)의 논리로
정당화해 상수로 선언**하는 것이 현 구조에서 가능한 최선입니다.

> 어느 쪽이든 **`net_radius` 는 영향받지 않습니다** — 그것이 이번 열람의 가장 큰 소득입니다.
