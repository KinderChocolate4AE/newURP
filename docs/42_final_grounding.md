## 1. A1 닫힘 — rho_air 보정 위험이 무의미해졌다

`docs/38` 은 A1(Xu 유효면적 평가 거리)을 **최대 레버리지 단일 항목**으로 꼽았습니다.
`rho_air` → τ → range_max → half_angle 이 줄줄이 매달려 있었기 때문입니다.

**τ 를 분해하면서 사슬이 끊어졌습니다.** `tau_flight = 0.15` 는 이제 Xu 의 **개방 시각**
(0.13 s, 외부 측정)에 앵커되고, 거리에 앵커되지 않습니다. 남은 종속은 `range_max`
(= τ_flight 시점의 병진) 하나이고, 그건 **비행 초반**이라 항력이 거의 작용하지 못합니다:

| `rho_air` | range_max | half_angle |
|---:|---:|---:|
| 1.225 (대기 기준) | 8.34 | 0.2353 |
| **1.513 (보정값)** | **8.22** | **0.2386** |
| 2.000 | 8.04 | 0.2439 |
| 3.000 (2배 과대) | 7.69 | 0.2543 |

**rho_air 를 대기값~2배까지 흔들어도 range_max 는 ±2%** 입니다.
⇒ **A1 은 실질적으로 닫혔습니다.** 보정이 틀렸어도 결론이 바뀌지 않습니다.
τ 분해는 전제를 복원한 것에 더해 프로젝트 최대 리스크도 제거했습니다.

## 2. A3 정량화 + 선언 — `net_radius` 2.0 → 1.77

`params.py` 가 스스로 경고한 항목입니다: *"equivalent-AREA radius, NOT worst-case
inradius -- r_in ≤ 2.0"*. 포획 판정은 도달집합 **전체**가 네트에 들어와야 하므로
구속하는 것은 최악방향입니다. τ_flight 시점 전개 형상의 최대 내접원을 측정:

```
투영 면적          26.21 m^2
등가면적 반경      2.888 m
최대 내접원 반경   2.565 m
비 (내접/등가)     0.888      (완전 정사각형이면 0.886)
```

논문 등가반경 1.997 m 에 적용 → **1.773 → 1.77 선언.**

> **상한임을 명시합니다**: 측정된 0.888 이 정사각형 값 0.886 과 거의 같은 것은
> flat-init 때문에 형상이 아직 평면 정사각형에 가깝기 때문입니다. 실제 곡면 입구는
> 더 찌그러지므로 **참 비는 0.888 이하**이고 1.77 은 낙관 상한입니다.

명제 N 경계: `a* = 2ρ/τ² = 39.3 m/s²` (2.0 기준 44.4에서 하향).
브래킷 [11, 78] 은 여전히 가로지릅니다 (P32 가 고정).

## 3. `tau_kill` — 근거가 고아였다

```
[구] "tau_deploy(0.4)의 1/4"     <- tau 는 이제 0.30. 근거가 존재하지 않는 값을 참조
[신] tau_kill >= tau_sense(0.10) + tau_decide(0.05) = 0.15
     하드킬 효과기도 **같은 센싱 사슬**을 쓴다. 0.15 = 3틱 (격자 위)
```

0.1 은 하드킬을 과대평가했습니다. **다만 주의**: τ_kill 을 키우면 하드킬 성공이 줄어
2차 지표(비손실 비율)의 **분모가 작아져 지표가 좋아 보입니다.** 그래서
**{0.15, 0.20} 을 선언된 sweep 축**으로 둡니다 — 2차 지표가 τ_kill 의 산물이 아님을
보여야 합니다.

## 4. 선회율 정합 — `adversary_omega` 는 inert 였다

원운동에서 필요 선회율은 `ω = a/v`:

```
공격자  a ∈ [11,78], v ∈ [8,30]  ->  필요 ω 최대 = 78/8 = 9.75 < 10
        4000 draw 전수: omega-구속 0.0%   => omega=10 은 **inert**. C-2 대기 불필요
limiter a=0.35a_att, v=att_speed ->  필요 ω 최대 = 27.3/8 = 3.41 > 2.5
        4000 draw 전수: omega-구속 1.9%   => ★ 추가 핸디캡. 의도한 것은 아니지만 유지
```

limiter 쪽은 우리에게 불리한 방향이므로 그대로 둡니다 — 결과를 보고 완화하면 소급 변경입니다.
`adversary_omega` 는 PENDING 에서 **해소(inert)** 로 옮겼습니다.

## 5. ★ 배선 버그 — 베이스라인이 공짜 하드킬을 쓰고 있었다

```
params.py: scripted.limiter_pressure = 1.0  "RESERVED -- env receives-and-ignores"
docs/29 §3.1: M4 가 limiter Box(4) idx3 을 **커밋 비트**로 재사용 (임계 0.5)

=> scripted_shaping_limiter() 가 idx3 = 1.0 을 반환한다
=> M4 스택에서 1스텝째에 n_committed = 4  (전 limiter 하드킬 커밋)
```

동결 env 에서는 idx3 이 무시됐으니 참인 문서였지만, **M4 가 그 차원을 살리면서 충돌**했습니다.
결과적으로 hold/ring/intercept 가 구분되지 않았고 (전부 bit-identical),
게이트가 무의미한 값을 재고 있었습니다.

**수정**: `run_episode(baseline_commit=False)` 가 기본 — 베이스라인은 커밋하지 않습니다.
하드킬 베이스라인이 필요하면 명시적으로 켭니다 (P9/P11 이 그렇게 옵트인).

> **이 버그를 못 잡았으면 논문의 모든 baseline 이 무의미했습니다.**
> 스윕 50런을 태운 뒤에 발견했을 가능성이 높습니다.

## 6. ★★ 게이트 확정 — 스크립트 조향 효과는 0 이다

`n=12` 에서 오가던 `±0.17` 은 **노이즈였습니다.** paired 로 `n=48`:

| | 라벨 | 침투 | 무력화 | 접촉 |
|---|---|---:|---:|---:|
| hold | PENETRATED 35 / NET_CAPTURE 9 / SPENT_FAIL 4 | 0.729 | 0.188 | 0.00 |
| ring | **동일** | 0.729 | 0.188 | 0.38 |

```
paired: ring 이 이긴 에피소드 0, 진 에피소드 0, 동일 48
=> 스크립트 조향은 임무 결과를 **하나도** 바꾸지 않는다. 접촉만 생긴다.
```

### 6.1 원인 — `kill_radius` 가 두 물리량을 겸한다

```
공격자가 피하는 반경 = repel_margin(1.0) x lam_range(1.0) x kill_radius = 0.75 m
```

`kill_radius` 를 접촉 기하로 grounding 하자(2.0 → 0.75) **limiter 의 조향 능력 전체가
같이 붕괴했습니다.** 한 심볼이 물리적으로 다른 두 양을 지고 있기 때문입니다:

| | 물리량 | 옳은 값 |
|---|---|---|
| (1) | 치사·접촉 반경 | **0.75 m** (docs/34 §6, 맞다) |
| (2) | 공격자가 존중해야 하는 이격 | **limiter 의 τ_kill 내 도달집합** |

(2) 는 limiter 의 **몸통**이 아니라 **도달집합**입니다. `env_sys` 가 하드킬 마진에
이미 쓰는 것과 같은 논리입니다:

```
r_avoid = kill_radius + 0.5*a_lim*tau_kill^2 + v_lim*tau_kill
        = 0.75 + 0.17 + 3.00 = 3.92 m      (a_att=44, v_lim=20 draw 기준)
```

**기존 2.0 보다 오히려 큽니다.** 즉 (2) 를 (1) 로 대체한 것이 과소 모델링이었고,
τ 때와 **같은 종류의 오류**입니다.

### 6.2 갈래 — 이번에도 우리에게 유리한 방향이라 판단이 필요합니다

```
(가) 분리한다   kill_radius(치사 0.75) 와 r_avoid(도달집합 ~4 m) 를 별도 심볼로.
                env_sys 의 하드킬 마진식과 동일한 유도이므로 내부 정합적이고,
                결과와 무관하게 물리적으로 옳다. 전제(조향 필요성)가 복원된다.
                구현: adversary/attacker_ladder 가 kill_radius 대신 r_avoid 를 쓰게 배선.
                ** 공격자 파라미터를 건드리므로 착취방지 규칙 2 와의 관계를 명시해야 한다.

(나) 수용한다   "치사반경을 grounding 하면 값싼 limiter 4기로는 손실회피형 FPV 를
                조향할 수 없고, net 드론이 혼자 해야 한다" 가 결과가 된다.
                MARL 협력 결과가 사라지고 경계조건 논문이 된다.

(다) 학습에 맡긴다  스크립트 ring 은 손튜닝 baseline 이므로 학습 정책은 다를 수 있다.
                다만 v_shot 압축 자체가 kill_radius 구(球)로 계산되므로
                (0.75³/2.0³ = 1/19 부피) 능력이 사라진 것은 정책과 무관하다. **약하다.**
```

**(가)를 권합니다** — τ 때와 같은 논리이고, 유도가 `env_sys` 안에 이미 있습니다.
다만 τ 때처럼 **전제를 복원하는 방향**이므로 단독으로 정하지 않습니다.
