## ★ 1. B-7 상술 — `engage_dist` 는 값이 아니라 **모델이 틀렸다**

### 1.1 우리 리포 내부가 서로 모순이다

```
configs/m2_l2_train.yaml :  finisher_p0 = (2, 0, 0),  x_fire = 11.0
                             -> 발사 시점 이격 = 9.0 m
prototypes/net_forward.py:  ENGAGE_DIST = 20.0 m
                             -> 네트 평가 거리 = 20 m
```

**2.2× 어긋나 있다.** τ_deploy = 0.4 는 20 m 기준이고, env 은 9 m 에서 쏜다.

### 1.2 게다가 "이격"과 "네트 병진거리"는 애초에 다른 양이다

공격자는 다가온다. 네트가 실제로 날아가는 거리는 이격보다 **짧다**:

```
net_travel(t) + v_att · t = separation      <- 이걸 풀어야 한다
```

이격 9 m, 공격자 20 m/s 로 풀면 네트 병진은 **6.3–7.3 m**, τ 는 **0.085–0.137 s** 다.

### 1.3 그래서 최적 발사점이 존재한다 — 그리고 우리는 그걸 지나쳐 있다

두 제약이 양쪽에서 조인다.

```
너무 일찍 쏨(이격 큼)  -> tau 큼 -> R_reach = 0.5·a·tau^2 커짐 + 네트는 이미 수축 중
너무 늦게 쏨(이격 작음) -> tau < 0.13 s -> 네트가 아직 안 펴짐
                                          (우리 시뮬은 flat-init 이라 이 구간을 과대평가한다)
              최적  =  tau = 0.13 s  (Xu 최대 면적 시각) 정확히 그 지점
```

| 이격 | τ | r_net | 모델 유효? | 허용 a_att |
|---:|---:|---:|:---:|---:|
| 20 m (현행 prototype) | 0.253–0.505 | 1.66–2.42 | 유효 | **13 – 76** |
| 9 m (현행 env, 폐로 보정) | 0.085–0.137 | — | **무효(미개방)** | — |
| **≈10–11 m (최적, τ=0.13)** | **0.13** | 2.3–2.7 (현실)<br>2.93 (상한) | 경계에서 유효 | **270 – 320** |

**⇒ 최적 발사점에서는 레이싱급(137)까지 비손실 포획이 기하학적으로 성립한다.**

### 1.4 그럼 하드킬은 필요 없나? — 아니다, 오히려 이게 논문이다

`허용 a_att`가 300 이라는 건 **완벽한 타이밍에 쐈을 때**의 값이다. 실제로는:

* 발사 창이 좁다 — 이격 ±1 m 만 어긋나도 τ 가 개방 경계를 넘나든다
* `net_radius` 는 **등가면적 반경**이지 최악방향 내접반경이 아니다(`params.py` 캐비앗). 최악방향은 더 작다
* 공격자는 **커밋에 반응**한다(A2 `dodge_amp=1.8`)
* 무엇보다 **공격자가 그 순간 개구 안에 있어야** 한다 — 그게 limiter 의 일이다

> **즉 "포획이 가능한가"는 기하 문제로 풀렸고, 남은 것은 "그 좁은 창을 맞출 수 있는가"다.
> 그건 정책 문제이고, 그게 우리 논문이다.** 하드킬은 창을 놓쳤을 때의 폴백으로 정확히 정당화된다.

`x_fire = 11.0` → **13–15 로 조정 권고**(이격 11–13 m, τ≈0.13). 다만 이건 scripted baseline 트리거일 뿐이고,
**학습 정책은 이 값을 스스로 찾아야 한다** — 그게 §6 의 주장이 된다.

**스펙시트는 상한을 확장하기 위한 것이지, 현 설정을 정당화하기 위한 것이 아니다.**

## D. 앵커 불필요 — 우리 설계 선언

외부 근거를 찾을 이유가 없는 것들. **"왜 이 값인가"의 답이 "우리가 그렇게 설계했다"인 파라미터.**

```
팀 구성      n_limiters=4, n_adversaries=1, finisher.K=1
회랑 기하    target(0,0,0), target_radius=1, ring_center(8,0,0), ring_radius=5,
             finisher_p0(2,0,0), adversary_start_x=24, episode_len=80
보상         lambda1..3, RewardSpec(b_net, w_kill, c_pen, c_trunc, c_lim)
게이트       theta_fire=0.9 (해석적 라벨 대비 CALIBRATED — 이미 근거 있음)
M4 sweep 축  Pk, R_nk, tau_kill, w_kill
알고리즘     MAPPO/COMA 하이퍼파라미터 전부
```

**단, 회랑 기하는 §1.3 의 최적 발사점과 정합해야 한다** — 앵커링이 아니라 **정합성** 문제다.
현행 `ring_center=8 m` 는 우연히 최적 발사 밴드(6–11 m) 안에 있다. 유지하면 된다.

`params.py` 의 DEAD/RESERVED 항목(`env.capture_thresh`, `omega_att_max=8.0`,
`limiter_pressure`, `finisher_slew_cmd`)은 **동결 계약 유물**이므로 앵커 대상이 아니다.
