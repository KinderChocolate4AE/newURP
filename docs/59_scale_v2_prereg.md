## 0. 근거 — 왜 스케일이 문제인가

뷰어 실측 (legacy 회랑):

```
스폰 거리 21.7~25.1 m · 공격자 14~26 m/s · 교전 전체 0.75~2.8 s
ring 대기 x=8 -- NK 경계(x=6)에서 2 m · tau_deploy 0.3 s = 성공 판의 ~40 %
공격자의 ring→NK 통과: 2 m / ~20 m/s = 0.1 s (2 tick)
```

이 스케일은 M2 셰이핑 게임의 legacy 이며 **교전 시간 자체가 비준된 적이
없다.** 이 렌즈로 기존 결과가 재해석된다 (전부 "legacy small-scale regime"
한정으로 재스코프):

- 접촉 42/42 NK-안 (docs/57·58) — NK-밖 교전 창이 기하적으로 ~2 m 폭
- 폴백 불능 — net 해소 후 잔여 비행 ~0.5 s, limiter 이동 여력 ~3 m
- LS≈SS — 편대 학습이 값어치를 만들 시간이 ~10 tick
- robust-clean knife-edge — 1초 순발력 게임의 산물일 가능성

**기존 결론은 폐기가 아니라 regime 한정이다.** 도구(계약·probe·뷰어)는 이식.

- PARK_POSITION (0,0,60): ring 50 과 근접해져 "ring 12배" 근거가 깨진다.
  스크립트 probe 에는 무영향 (v_shot 기여 0 조건은 유지 — 공격자 회랑에서

## 2. 격리 규율

- 브랜치 `feat/scale-up-v2`. main 라인(feat/l2-mappo-train)과 섞지 않는다.
- 배선 = **config overlay dict 하나** (`shepherd/scale_v2.py`). 새 코드 경로
  없음. overlay 미적용 시 기존과 **비트 동일** (P85 강제).
- legacy 수치와 v2 수치를 같은 표에 섞지 않는다 (P78 규율 동형).

## 3.1 V4 1차 결과 + V5 1차 육안 검사 기록 (2026-08-07b)

V4 1차 (episode_len=400, n=100): capture 10 / 침투 61 / **절단 29**.
V5 (Hyunjun): 스케일감 승인 · cone 시각화 요청 · "절단 판이 포획처럼 보인다".

- **절단 29% = 지평선 산술 오류로 판정** (ep4 = t396 clean 발사 후 해소 전
  절단 — 포획 진행 중; ep9 = 저속 draw 미도달). "A2 배회·시간상수" 의심은
  **철회** (분포 요약의 과잉해석). → episode_len 480 정정 후 V4 재실행.
- **hold 기저선의 clean 게이트 붕괴는 실재** (fire 19/100): ring x=50 이
  cone(x≲32)과 분리 — v2 에서 limiter 기동이 구조적으로 필수가 됐다.
  이것은 버그가 아니라 **v2 의 첫 발견**: "대기점-cone 관계" 가 설계 변수.
- limiter 정책 확인 (Hyunjun 질문): V4 는 hold(무개입 정지) 기저선.
  fallback 대비 근접 이동은 미구현 — scripted/학습이 채울 자리.

## 3.2 V4-800 확정 + V5 2차 육안 판독 (2026-08-07c — Hyunjun 판독, 수치 실증)

V4-800 (n=100): **capture 15 / 침투 85 / 절단 0**. legacy(16/84)와 근사 —
스케일 22배에도 hold 기저선 불변 = **새 대응시간을 아무도 안 쓴다**
(fire 22/100·무개입 limiter·등속 공격자).

육안 판독 → 수치 실증 3건:

1. ★ **ep1: NK-밖 자연 발생 fallback 창** — miss 해소 후 공격자의 회피
   오버슛→반전에서 **1.25 m/s 준정지 @ d_asset=16.1 m** (NK 경계의 2.7배
   밖, ~0.45 s). legacy 전 캠페인(oracle 사슬 포함)에서 못 찾던 NK-밖 창이
   **baseline 에피소드에 자연 발생** — v2 스케일에서 회피 기동의 관성
   대가가 창을 만든다. **limiter fallback 미구현이라 그냥 지나감.**
2. ep26: 유사 정지(2.7 m/s)이나 d_asset=6.7 — NK 경계 직상 한계 사례.
3. ep94 (저속): 조준 정상·무발사 원인 = **v_soft 천장 0.728 < 게이트 0.9,
   clean 0 스텝** — hold limiter(x=50)가 종말 탈출로를 못 덮음. 발사 계약
   정상, limiter 부동이 원인. **위협 v3 + limiter 재학습으로 해결 예상**
   (Hyunjun 가설, 기전 합치).

뷰어: cone 승인 + m 격자(10/25/50 자동) 추가.

## 4. v2 이후 순서 (뷰어 승인 후)

```
1. miss/capture 재분류 + 뷰어 대조
2. ★ 위협 계약 v3 설계 (Hyunjun 축 3개, 2026-08-07 지시 누적):
     (i)   종축 속도 전략 -- 등속 순항 탈피 (급가속 터미널 스프린트·감속
           페인트). 능력 v_max=1.5×att_speed 는 기 선언, 행동만 미구현
     (ii)  횡 반응성 -- limiter 회피 (P84 로 현 A2 부재 확정)
     (iii) 스폰 불규칙성 -- 거리 브래킷 확장 + ★ 접근 방위 랜덤화.
           현행은 +x 고정 = limiter 가 깔린 방향에서만 옴 (스폰 290~310 균일)
   파급: (iii) 이 "회랑" 프레임을 해체 -- ring 축-고정(50,0,0) 가정 붕괴.
   대응 후보 = 표적 중심 전방위 배치 or **탐지→방위 식별→재배치** 를 문제에
   포함 (후자가 mode scheduling 연구 질문의 자연스러운 무대). finisher slew
   상한의 방위 추종 가능성은 검증 항목. 경로 A/B 결정과 한 계약으로 묶는다
3. NK-밖 창 재측정 (legacy 의 42/42 NK-안이 스케일 산물이었는지 판정)
4. 3-way 는 그 뒤 (계약 v3 확정 후)
```

판정식·선언값은 결과 후 불변경. ring_center 등 "설계 변수" 의 조정은
새 사전등록으로만.
