## 1. 진단 정정 — 시뮬레이터는 v0 를 이미 쓴다

```python
# game/viability.py  _v_shot_with_accels
endpoints = x_att + v_att*tau + 0.5*accels*tau**2        # v0*tau 항 존재
# env.py  _net_center   (point_mass judge)
net_center = p_att + v_att*tau                            # 완벽 lead 조준
```

`point_mass` judge 에서 두 식의 `v0*tau` 가 **정확히 상쇄**되어 `w = 0.5*a*tau^2` 만
남는다. 즉 명제 N 은 "정지에서 등가속" 가정이 아니라 **"네트를 완벽히 예측 조준한다"**
가정의 결과다. 순수 이중적분기의 tau-도달집합은 표류점 `p0 + v0*tau` 를 중심으로 한
**정확한 공**이며, '오뚜기' 형상은 속도 상한·선회율 상한을 넣을 때만 나타난다. 그리고
그 둘은 도달집합을 **줄이므로**, 지금의 등방 공은 참 도달집합의 **보수적 외포**다
(공격자에게 관대 = 우리에게 불리 = 안전한 방향).

> 코드에 `_feasible_turn` 이 이미 있으나 `viability.turn_limited=False` (RESERVED).

## 2. 그런데 M4 는 `point_mass` 를 쓰지 않는다

```
configs/m2_l2_train.yaml:36    judge: se3_cone
```

`se3_cone` 에서는 `net_center` 가 **호출조차 되지 않는다.** 포획은 finisher 의
물리적 자세가 만드는 원뿔로 판정한다:

```
_caught_se3_cone : apex = T_F,  axis n_F = R_F . e_net,  half-angle theta,  band [0, R]
sim/analytic.py:130 :  e <- slew(e, e_cmd, omega_max * dt)      # 대원 회전, rate-limited
```

**lead 조준이 공짜가 아니라 `attitude.omega_max` 에 묶인 행동**이다. 확인:

```
R * tan(theta) = 8.22 * tan(0.2121) = 1.770 m   == net_radius (1.77)
=> 원뿔의 최대사거리 횡단반경이 곧 rho. a*(정렬완료) = 2 rho / tau^2 = 39.3  (일치)
```

즉 **명제 N 은 `psi = 0` (조준 오차 0) 인 단면**이다. 일반형:

```
a*(psi) = 2 d (tan theta - psi) / tau^2
```

| psi | 0° | 1.1° | 2.9° | 5.7° | 8.6° |
|---|---|---|---|---|---|
| a\* | 39.3 | 35.7 | 30.2 | 21.1 | 11.9 |

그리고 `psi` 를 지배하는 것은 **추적 문제**다:

```
omega_req = v_perp / d          표적을 따라가는 데 필요한 시선 각속도
omega_req > omega_max  =>  psi 가 누적된다 = 추적 실패
v_perp* = omega_max * d         (d = 8.9 m 에서 17.8 m/s)
```

**이것이 두 번째 경계다.** 첫 번째(가속도) 경계와 물리적으로 독립이고,
신청서 핵심 그림 1(속도 x 기동성 지도)의 **속도 축**에 정확히 대응한다.

## 4. ★★ ④ 재해석 — limiter 는 무력하지 않다, **상쇄한다**

`docs/42 §6` 은 paired n=48 에서 hold 와 ring 이 **48/48 동일 라벨**이라고 기록했다.
그 페어드 테스트가 쓴 공격자는 기본값 A1(jink 0) 이다. 그런데 지금 실측은 같은 조건에서

```
hold  v_perp 0.44 m/s   omega 구속 0.0 %
ring  v_perp 7.27 m/s   omega 구속 44.8 %       <- 궤적은 16배 다르다
```

**궤적이 16배 다른데 임무 결과가 하나도 안 바뀌었다.** 이건 "조향이 아무 일도 못 한다"
가 아니라 **"조향이 두 가지 반대 효과를 동시에 만들고 정확히 상쇄된다"** 는 뜻이다:

| | limiter 가 하는 일 | 방향 |
|---|---|---|
| (i) | 도달집합에서 가속 방향을 잘라낸다 (`_feasible_limiter`, `kill_radius`) | 유리 |
| (ii) | 공격자를 옆으로 밀어 v⊥ 를 만든다 → 네트 드론이 조준을 못 따라간다 | **불리** |

`kill_radius` 를 2.0 → 0.75 로 grounding 하면서 (i) 이 붕괴했다 (부피 1/19).
남은 것은 (ii) 뿐이었고, 그래서 ring 은 **비용만 있고 이득이 없는** 배치가 되었다.

### 4.1 갈래가 하나 늘어난다

```
(가) 치사반경/회피반경 분리    (i) 만 복원한다. (ii) 는 그대로 남는다.
(나) 음성 결과 수용            "값싼 limiter 4기로는 조향 불가"
(다) 두 채널을 분리해 측정     (i) 과 (ii) 를 따로 재고, 정책이 (i) 을 얻으면서 (ii) 를
     ★ 새로 생김               피할 수 있는지를 학습 문제로 세운다.
```

**(다) 가 논문으로서 가장 강하다.** 협력의 산출물이 "위치 차단"이 아니라
**"조준 가능한 상태를 만들기"** 가 되고, 이건 손튜닝 ring 이 못 하고 학습 정책만
할 수 있는 종류의 조율이다 — limiter 는 몰되 **네트 드론이 겨눌 수 있는 방향으로**
몰아야 한다. 스크립트 baseline 이 실패한 이유까지 같은 틀에서 설명된다.

또한 (다) 는 **공격자 파라미터를 건드리지 않는다** — 착취방지 규칙 2 안전.

## 5. 규율 — 방향성과 앵커

**자기 정정.** 이 조사 초반에 나는 `attitude.omega_max = 2.0` 이 외부 앵커 없는
ASSUMED 값이라고 말했다. **틀렸다.** 그건 `params.py` 의 **구** 항목이고, M4 는
2026-07-29 에 이미 재선언했다: *Pliska et al. (RA-L 2024) 실기 요격기 최대 선회율
2 rad/s*. 앵커는 있다.

다만 **앵커의 대상이 다르다**: Pliska 값은 **기체 선회율**이고, 여기서는 **네트 지향축
slew** 로 쓰인다. 네트가 기체에 고정(body-fixed)이라는 축소자세 모형에서만 같은 값이다.
짐벌 탑재면 더 빠르고, 그러면 (ii) 의 비용이 줄어 결론이 달라질 수 있다.
→ `SWEEP_AXES` 에 `{1.5, 2.0, 3.0}` 으로 올렸다.

**방향성 경고.** 조준오차 항을 넣으면 `a*` 가 **내려가** 협력 필요 영역이 넓어진다 —
우리에게 유리한 방향이다. 상쇄되어야 할 항(공격자 선회율 제한 `omega_att = 10`)은
`8 x 0.30 = 2.4 rad ≈ 137°` 로 사실상 전 방향이라 **실질 상쇄가 없다**. 그러므로
유리한 쪽만 넣는 셈이 된다. 방어 논리는 τ 때와 같다:

1. `omega_max` 는 **외부 앵커 값**이고 우리 자유도가 아니다.
2. 결과를 보기 **전**에 선언하고, 점값이 아니라 **sweep 축**으로 둔다.
3. `psi` 는 새 파라미터가 아니라 이미 있는 두 선언값(`omega_max`, `tau`)의 **귀결**이다.

| 39.3 – 78.0 | 904 | **0.000** | [0.000, 0.0042] | 명제 N — 예외 없음 |

`hold` 배치 · A2(jink 0.6) · **n=1500**. 50 % 교차점 = **23.82 m/s²**.
`intercept` 배치(n=1200)도 같다 — 교차점 23.46, 경계 위 네트 포획 0/731.
두 배치 합산 **경계 위 네트 포획 = 0 / 1,635**.

### 9.3 ★ 독립 계측 두 개가 만난다

`slew_audit` 로 **잔여 조준각** `psi` 를 따로 쟀다 (A2 jink 0.6 · hold · 밴드 안 스텝):

```
psi_med = 4.26 deg        (FREE_CAPTURE 구간, n=316 스텝)
psi_med = 10.94 deg       (SHAPING_NEEDED 구간, n=301 스텝)
```

이것을 §4 의 일반형에 넣는다:

```
a*(psi) = 2 * d * (tan(theta) - psi) / tau^2        d = 8.22, theta = 0.2121, tau = 0.30

  psi = 0        ->  39.33      (= 2*rho/tau^2, 명제 N)
  psi = 4.26 deg ->  25.75      <-- 예측
  곡선 50% 교차   ->  23.82      <-- 관측     편차 7.5 %
```

**`psi` 는 포획 결과를 전혀 보지 않고 잰 값**(지향축 기하)이고, 곡선은 포획 결과만으로
그린 것이다. 두 값이 6.6 % 안에서 만난다.

### 9.4 세 구간

```
EASY            a < 25.8      네트 포획 0.832 (253/304)   -- 손튜닝으로도 잡힌다
BAND_AIM        25.8 ~ 39.3   네트 포획 0.010 (3/292)     <-- 학습이 먹을 자리
SHAPING_NEEDED  a >= 39.3     네트 포획 0.000 (0/904)     -- 원리적으로 불가능

hold n=1500 기준. 두 배치 합산으로는 BAND_AIM 3/518, 경계 위 0/1,635.
intercept 배치는 BAND_AIM 에서 **물리 요격으로만** 35/226 = 15.5 % 를 막는다
(네트 포획은 0/226). 즉 이 구간조차 손튜닝이 닿는 유일한 길은 기체 파손이다.
```

**④ 가 여기서 완전히 닫힌다.** 채널 분리에서 잰 `ring` 의 `v_perp` 0.44 -> 7.27 m/s 는
정확히 **두 번째 경계를 왼쪽으로 미는** 방향이다. 즉 ring 은 채널 (i) 로 번 것을
채널 (ii) 로 되돌려준 것이 아니라, **애초에 경계를 악화시키는 조성**이었다.
학습 목표 문장이 한 단계 구체화된다:

> 도망갈 길을 막는 조성이 아니라 **공격자의 횡속도를 줄이는** 조성.

### 9.5 한계 (과대 해석 금지)

1. **중앙값 대 중앙값 비교이지 유도가 아니다.** `psi` 는 `a_att` 에 따라 커지므로
   (FREE 4.26° vs SHAPING 10.94°) 단일 중앙값을 쓰는 것은 1차 근사다. 곡선 전체를
   `a*(psi(a))` 로 재현하는 것은 후속 항목으로 남긴다.
2. **이 곡선은 손튜닝 기준선의 것이지 학습 정책의 것이 아니다.** 경계 위 0 % 는
   "시스템 성능"이 아니라 **문제 정의**다. 발표·문서 어디서도 이 구분을 지운 채
   쓰지 않는다.
3. `psi` 는 밴드 안 스텝 기준이고 곡선은 판 기준이다. 집계 단위가 다르다.

### 9.6 ★ 정정 8 — 계측 조합 오류 (자기 발견)

곡선의 `intercept` 계열을 처음에 `limiter_mode="hold" + baseline_commit=True` 로
돌렸다. **커밋 비트는 limiter 행동 벡터(idx3)에 실려 있고 `hold_position_limiter()`
는 그 자리를 0 으로 두므로, 이 조합은 `hold` 와 완전히 같다.** 300판 라벨 분포가
`hold` 와 **완전 일치**(PENETRATED 233 / NET_CAPTURE 46 / SPENT_FAIL 21)해서 잡았다.
재현 조합은 `limiter_mode="intercept" + baseline_commit=True` 다
(`results/intercept_baseline.json` 대조).

교훈: **두 조건의 결과가 같으면 먼저 "정말 두 조건인가"를 의심한다.**
